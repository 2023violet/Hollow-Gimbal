## 会话、准入与结果

- `FULL_PROFILE` 要求七个阶段全部合格。`SELECTED_STAGES` 可做子集诊断，J/B 可单独执行。电角零点依赖 Rotor，K/D 依赖本会话 J/B 和单独登记来源、Capture ID、采样时刻的 Kt。未知 Kt 返回 `DATA_REQUIRED`。带 LUT 的流程先以独立 Holdout 验收冻结表，再用正式 Encoder 将原始码转换为 Rotor 和零点阶段的机械角。示例的采集方向 −1 与 Rotor 相对方向 −1 组合成 Runtime 方向 +1。
- 会话和采集绑定电机、编码器、电流采集配置和机械坐标。UInt32 会话序号按半程规则判断前进。每阶段携带来源、Capture ID、样本序列及统一单调时钟。相异来源、重复或倒序序号、超龄、无效前提或异源身份被显式拒绝。采集 ID 在会话内唯一，包含 LUT Holdout 和 Kt。有限值、饱和、激励、样本数、时间间隔、覆盖率和残差继续由原生估计器约束。
- 统一结果保留每阶段状态、失败原因、采样时间和质量，包含 ADC/机械方向/电角零点的准入结果，以及 R/L、LUT、J/B、K/D 计算与来源。独立通过阶段可用于诊断。只有请求范围全部成功且正式 Calibration Admission 通过，才可生成待审核应用候选。取消、新会话或身份失配会撤销候选。多实例独立管理序号与暂存，活动会话拒绝重新 `init`。

## 审核、显式应用与运行安全

`foc_cal_application_start()` 绑定旧实例的一致快照和实际 Pipeline 政策。旧实例需 `DISABLED`、无故障、已确认 `INHIBIT`，并且没有待处理生命周期动作或 STOP。调用方应保持旧 Runtime 和事件入口静止。准备阶段复用 Control Plane 的初始准入及 Config Inspector 的稳定参数 ID；ADC 与 LUT 由独立候选和新实例读回。演示中电角零点 `0x1002` 从 0.37 rad 变为 1.2000237 rad，Inspector 报 `REINITIALIZATION_REQUIRED`。

独立复核身份后才能显式初始化调用方提供的独立 Runtime 与 Encoder。应用前再次核对绑定、当前安全状态和候选；测试覆盖错误身份、未审核、取消、代次过期、挂起请求、STOP、故障、INHIBIT 确认失败、带 Host 观察回调的原实例及无效配置。拒绝路径保留旧 Runtime 及目标存储。实际运行读回新旧实例均 `DISABLED/INHIBIT`，接受的 UPDATE 均为 0，旧 Motion Session 保持 0。新 Encoder 使用复制后的 LUT，同一原始码 256 得到 264，后续会话重启不撤回已初始化实例的 LUT。

应用沿用 SOFT-02 保护和原控制、输出、采集政策，K/D 保留为建议值。R/L 和 J/B 为辨识结果，不触发 PI 写入。SOFT-03 Schema 2 现有兼容检查独立报告 `IDENTITY_MISMATCH(-9)`，因为原策略记录身份含旧电角零点。标定通过、候选审核、新 Runtime 读回、配置持久化分开报告。示例 `CONFIGURATION_PERSISTED=false`，SOFT-05 无存储写入入口。
