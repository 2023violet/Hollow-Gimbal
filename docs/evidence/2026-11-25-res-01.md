# RES-01｜RAM 与 ROM 收缩（不加功能）

2026-11-25，分支 `codex/falconfoc-v2-vm01a`，基线 `2a2f3b5`（ENC-01 与文档收尾之后）。只做软件验证，没有上板。

## 结论

两项改动都不改变行为，只收缩资源：

1. 标定工作区合并：CAL-2、CAL-3/4/7 与 CAL-8/9 三段暂存数据改成一个联合体，RAM −8,096 B。
2. ARM 镜像启用部分 LTO：默认镜像 Flash −5,996 B，带存储镜像 −6,268 B。

UART 线上录制 6,365 条与 ENC-01 逐字节相同。CAL-9 的拟合数值与 ENC-01 一致。

| 镜像 | 改前 | 改后 | 变化 |
| --- | ---: | ---: | ---: |
| 默认 Flash | 109,916 B | 103,920 B | −5,996 B |
| 带存储 Flash | 115,532 B | 109,264 B | −6,268 B |
| 默认 RAM | 22,132 B | 14,036 B | −8,096 B |
| 带存储 RAM | 22,276 B | 14,180 B | −8,096 B |

带存储镜像距离 122 KB 程序上限（0x0801E800）还有约 15.3 KB（原来约 9.2 KB）。RAM 的变化：

- `calibration`：9,760 → 6,784 B；
- `foc_board_cogging_state`：6,200 → 1,084 B。

报告：[默认](2026-11-25-res-01/fwsight-default.txt)、[带存储](2026-11-25-res-01/fwsight-persist.txt)。

## 改动

- **分桶独立成类型**：`foc_board_cal_bins` 包含两个方向的均值和计数，共 5 KB。
  - `foc_board_cogging` 只保存指向分桶的指针（调用方提供存储）。
  - `foc_board_cogging_init` 保留这个指针，且不写分桶；`begin` 时清空分桶。
  - 指针为空时，采样被忽略，拟合返回 FAILED。
  - `foc_board_encoder_lut_fit` 改为接收分桶。
- **校准管理器工作区**：`struct foc_board_calibration` 末尾新增匿名联合体，成员名不变，`foc_board_calibrate.c` 不需要改名。三个分支：
  - CAL-2：扫描样本、转子估计器、偏置估计器；
  - CAL-3/4/7：H0 记录环、待对齐记录、历史记录、R/L、磁链、惯量上下文；
  - CAL-8/9：分桶。`attach_cogging` 时借给齿槽采集。
- **生命周期依据**：
  - 每段在开始时初始化自己的分支；结果和回读字段都在联合体之外。
  - H0 只在 `record_active` 置位时写记录环，这个标志只在 RL_D 和 INERTIA 入口置 1。CAL-8/9 启动时再清一次。
  - CAL-8/9 只能单独运行。
  - ADC 估计器留在联合体外，因为空闲自动零点会在 H0 里用它。
  - `_Static_assert` 检查三个分支起点相同。
- **部分 LTO**：
  - 交叉编译时 `firmware/at32f415/CMakeLists.txt` 统一加 `-flto`，链接时加 `-flto -Os`。
  - 静态检查依赖的文件（`main.c`、`foc_board.c`、`foc_board_boot.c`、两个 supply 文件、`foc_board_expectation.c`）用 `-fno-lto`。这样 main 序言、选择链调用顺序、输出适配器摘要与基线可比。
  - 工具链文件改用 `arm-none-eabi-gcc-ar` 和 `arm-none-eabi-gcc-ranlib`。没有 LTO 插件时，归档里的 LTO 目标文件没有符号索引。
  - Host 构建不受影响。
- **fwinteg 静态检查**：
  - `no_unexplained_symbols_removed` 换成 `protected_symbols_present`。受保护的入口：
    - `main`；
    - 选择链：expectation、supply、`boot_select`、`select_with`、`qualify`；
    - `foc_board_output_submit`；
    - `foc_board_init_with_calibration`、`foc_calibration_admit`；
    - `foc_runtime_request_inhibit`、`foc_device_output_inhibit`、`foc_safe_supervisor_tick`。
  - 相对基线消失的符号只列出不判失败：LTO 会内联辅助函数，或给它们加 `.lto_priv`/`.isra` 后缀。
  - 例如 `foc_safe_gate_output` 和 `foc_pipeline_step_guarded` 已内联进调用者，代码仍在镜像里。
- **SIL `encoder-lut`**：
  - CAL-9 之后在同一次上电里再跑 CAL-8：两张表都要 VALID，CAL-9 表逐节点不变。
  - 断电重启后两张表都要恢复。

## 验证

- **单元测试**：
  - `test-foc-board-cogging` 新增 `test_borrowed_bins`：`init` 保留指针且不碰分桶；`begin` 清空分桶；无分桶时采样被忽略、拟合 FAILED、表不变。
  - `test-foc-board-encoder-lut` 新增空分桶返回 FAILED 的检查。
- **SIL `encoder-lut`**（[结果](2026-11-25-res-01/sil-encoder.json)）：
  - CAL-9 DONE / VALID，节点最大误差 6.88 计数，一致性 0.991；位置误差 RMS 0.00759 → 0.00018 rad。这些与 ENC-01 相同。
  - 同一次上电的 CAL-8 DONE / VALID，一致性 0.635；编码器表仍然启用，逐节点不变。
  - PARAM_SAVE 后断电重启，编码器表与齿槽开关都恢复。
- **SIL `cogging`**：数值同 COG-01，全部通过。
- **UART 线上录制**：6,365 条 PARAM_READ/PARAM_WRITE 应答与 ENC-01 逐字节相同。
- **fwinteg `run1`**：VERDICT PASS，0 findings；三套工具链各 133 项全部通过。五个 ARM 镜像的 9 项静态检查全部 PASS：
  - 受保护符号一个不缺；
  - main 序言、选择链顺序、WFI 分支、输出适配器都与基线一致或在已审核范围内。

  相对冻结基线 `211b226`，有 61–62 个符号因内联或本地化消失（只列出）。各镜像大小：

  | 镜像 | 大小 |
  | --- | ---: |
  | 默认 | 103,920 B |
  | verification | 104,200 B |
  | 默认 capture | 105,196 B |
  | verification capture | 105,476 B |
  | trace | 105,048 B |

- **其他**：固件 Host 20 项（含 SIL）、clang 矩阵 11 个工程、质量门禁（含 CMake 格式）全部通过；SDK 技术门禁 PASS。

## 局限

- LTO 之后，`-fstack-usage` 只覆盖不参与 LTO 的文件，fwinteg 收集的 `stack-usage.su` 不再代表整个镜像。栈余量仍由 `stack-budget.ld` 的 4 KiB 断言把关，RAM 降了约 8 KB。
- 联合体的安全性来自"各段不同时运行"。以后新增与 CAL-8/9 组合的阶段，或在空闲时使用记录环，都要重新检查生命周期。
- SIL 发现一个与本改动无关的现象：`encoder-lut` 的被控对象是 84 周期/圈、0.004 N·m 的齿槽，CAL-8 一致性偏低：
  - CAL-9 之后在同一次上电里跑：0.635（VALID）；
  - 断电重启后再跑（工作区本次上电从未用过）：0.42（INCONSISTENT）。

  分桶在 `begin` 时整体清空，所以这不是复用造成的。原因是位置环在正反两个方向的滞后不同，使 84 次谐波的相位错开。这与契约 28.7 "84 周期需台架确认"的局限一致。
