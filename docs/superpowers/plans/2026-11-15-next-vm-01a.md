# NEXT-VM-01a Host Virtual Motor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a deterministic Host-only PMSM current-loop executable that reuses FalconFOC Runtime, Device, Safety, Current PI, Encoder, and ADC contracts without changing the locked Board1 firmware.

**Architecture:** Add a standalone `simulation/` CMake project. `foc_virtual_motor` owns only a caller-owned RK4 PMSM plant and sensor conversion. `foc_virtual_current` owns a virtual clock, Runtime instance, accepted-output adapter, encoder publication, and deterministic scenarios. The virtual output callback accepts only validated Host requests; real Board1 code remains untouched.

**Tech Stack:** C11, CMake/Ninja, existing `falconfoc-pipeline`, `foc_encoder`, `foc_device`, and standard C math only.

**Spec:** `NEXT-VM-01a` user-provided execution prompt dated 2026-11-15.

## Global Constraints

- Do not modify `firmware/at32f415/src/foc_board.c`, Board1 hardware configuration, Runtime lifecycle APIs, Serial, Protocol, or real safety behavior.
- Do not add dynamic allocation, RTOS, MCU headers, Python, or external dependencies.
- Use one deterministic virtual microsecond clock and H0=200 us / H1=500 us.
- Apply a PWM request to the Plant only after the Host output adapter accepts a validated UPDATE.
- Feed ADC through `foc_device_decode_sample` and feed encoder codes through `foc_encoder_update` before H1 publication.
- Preserve the real Board1 output lock and report `NEXT-SW-AUDIT-01` as pending.

## Review Focus

- Invalid Plant parameters or `dt_s` must leave state unchanged; owned by Plant tests.
- ADC phase order, offsets, quantization, and current sign must match Device decoding; owned by sensor/current-loop tests.
- Encoder first-frame position, wraparound, and direction must not fabricate a valid speed; owned by virtual sensor tests.
- Rejected UPDATE and STOP must prevent new Plant voltage and preserve/close Runtime transaction state; owned by virtual Runtime tests.
- Replayed virtual time and commands must produce identical state and fingerprint; owned by executable scenario tests.

- `struct foc_virtual_motor_params` contains `rs_ohm`, `ld_h`, `lq_h`, `psi_f_wb`, `pole_pairs`, `inertia_kg_m2`, and `damping_nm_s`.
- `struct foc_virtual_motor_state` contains `id_a`, `iq_a`, `mechanical_position_rad`, and `mechanical_velocity_rad_s`.

- `int foc_virtual_motor_step(struct foc_virtual_motor *, double v_alpha_v, double v_beta_v, double dt_s)` advances one RK4 step and rejects invalid inputs without mutation.
- `int foc_virtual_motor_apply_duty(struct foc_virtual_motor *, const struct foc_device_pwm_request *, float vbus_v, double dt_s)` converts accepted phase duties to alpha/beta voltage and calls the RK4 step.
- `int foc_virtual_motor_make_adc(const struct foc_virtual_motor *, const struct foc_device_adc_config *, uint32_t seq, uint32_t timestamp_us, struct foc_device_adc_raw *)` creates quantized VBUS/phase-current ranks with validity bits.
- `int foc_virtual_motor_make_encoder_code(const struct foc_virtual_motor *, const struct foc_encoder_config *, uint16_t *)` converts continuous mechanical position to a quantized wrapped raw code.

### Task 2: Build the virtual Runtime/current-loop harness

**Files:**
- Create: `simulation/include/foc_virtual_current.h`
- Create: `simulation/src/foc_virtual_current.c`
- Create: `simulation/tests/test_foc_virtual_current.c`
- Modify: `simulation/CMakeLists.txt`

**Interfaces:**
- `struct foc_virtual_current_profile` owns `foc_virtual_motor_params`, VBUS, ADC/PWM/encoder configuration, Current PI configuration, Safety configuration, Runtime motion/prediction configuration, and H0/H1/Foreground periods.
- `struct foc_virtual_current` owns the Plant, Runtime, Encoder context, output journal, virtual time, sequence counters, and replay hash.
- `int foc_virtual_current_init(struct foc_virtual_current *, const struct foc_virtual_current_profile *)` initializes the Plant, Encoder, Runtime, and initial accepted INHIBIT without calling `foc_board_init()`.
- `int foc_virtual_current_publish_iq(struct foc_virtual_current *, float id_a, float iq_a)` publishes a strictly newer Current command at the current virtual time.
- `int foc_virtual_current_run_until(struct foc_virtual_current *, uint32_t target_us)` advances deterministic events in this order: apply old output to Plant, publish H1 sensor if due, run Foreground, then run H0 with ADC and lifecycle action.
- `int foc_virtual_current_request_stop(struct foc_virtual_current *)` uses `foc_runtime_revoke_command()` and lets H0 acknowledge the stop.
- `int foc_virtual_current_reject_next_update(struct foc_virtual_current *)` injects one Host adapter UPDATE rejection without altering the production pipeline.
- `int foc_virtual_current_snapshot(const struct foc_virtual_current *, struct foc_runtime_snapshot *)` reads the Runtime snapshot at quiescent points.
- `const struct foc_virtual_motor_state *foc_virtual_current_motor(const struct foc_virtual_current *)` exposes read-only Plant state for scenario reporting.
