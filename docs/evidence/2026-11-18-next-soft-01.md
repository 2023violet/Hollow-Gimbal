## 设备模型与数据来源

| 类别 | 数量 | 来源和权限 |
| --- | ---: | --- |
| CONFIG `0x1001–0x100A` | 10 | 读取实际 Runtime 的不可变初始 Motion/Impedance config。5 项只读，包括极对数、电角偏移、Kt、机械坐标身份和 Position 速度上限。5 项可校验暂存，包括运动 q 电流上限、转矩上限、K 上界、D 上界和前馈上界。 |
| COMMAND `0x2001–0x2005` | 5 | 参考位置、速度、K、D、前馈。全部通过正式 IMPEDANCE 整条命令接纳。 |
| STATUS / TELEMETRY `0x3001–0x300F` | 15 | Runtime 一致快照。模式、Safety、Fault、Session、命令观察序号/源时间、Sensor 源时间与有效性、输出动作/确认/UPDATE、INHIBIT pending、机械位置/速度及 Pipeline 状态。 |
| ACTION `0x4001–0x4005` | 5 | STOP、隔离命令超时恢复、SET_MODE、ARM、START。转交现有 Runtime，并以已有生命周期结果或快照确认。 |

合计 **30 项参数和诊断、5 个动作描述符**。静态 C 表描述 ID、稳定名称、值类型、物理单位、范围、权限、重新初始化和持久化属性以及语义。5 项静态可编辑配置的 `requires_reinit` 为 true，本轮所有描述符的 `persistable` 为 false。读写不通过结构体偏移生成 ID。

枚举与查找通过 `foc_parameter_count/at/find`，读取与校验使用 `foc_parameter_read/get_range/validate/write_access`。只有命令观察发生后才返回命令序号和源时间。无有效 H0 机械观测时，Sensor 位置、速度和时间返回 `ERR_SENSOR`。多个字段要求同一代次时直接读取一份现有 Runtime Snapshot。运行命令字段由生产者随整条输入持有，可查询接纳状态。参数模块没有命令缓存或诊断镜像。

### 暂缓项及原因

- **J/B 和默认 K/D** 分别来自应用模型、辨识候选和命令生产者，目前未接入统一运行配置拥有者。
- **Encoder CPR、机械方向、Kt/极对数/电角偏移的写入** 需绑定位姿、标定和设备身份。Kt、极对数、偏移可从已经生效的 Runtime 配置读取。
- **电流环内层电流限额的实时读写** 涉及 Pipeline H0 提交的 Current 上下文。Foreground 使用不变的 Runtime 外环配置，初始准备使用调用方 Pipeline 配置。这样避免整结构写入时的读取竞争。
- **实际/模型 q 电流、电流限幅、真实转矩、实机校准质量的通用诊断** 缺少一致可信的公开 Runtime 快照源。Host Plant 的独立观测属于它自己的 API。
- **远端枚举、持久化、版本迁移和自动标定编排** 属后续工作。本轮仅提供本机 C11 设备模型与接纳。

## 写入和实际生效

| 路径 | 准入与结果 |
| --- | --- |
| `foc_parameter_prepare_initial()` | 在独立副本校验类型与有限数值、批量编辑的唯一性、运动 q 限额与 Pipeline 上限及 Kt/电流关系。成功是 `VALIDATED`。使用同一 Pipeline 配置对新实例调用原 `foc_runtime_init()`，通过成功结果及读取实际值验证安装。 |
| `foc_parameter_stage()` | 从实际配置准备独立候选。当前 Session、无 Fault、DISABLED、INHIBIT 确认且无待处理 STOP 才接纳。运动 q 限额可保持或降低。失败保留候选原值。成功仍为 `VALIDATED`，原实例继续使用原配置。 |
| `foc_parameter_publish_impedance()` | 校验整条命令的数值范围、机械坐标、会话、当前模式和准入。Runtime 校验发布顺序与源时间并处理邮箱。成功为 `ACCEPTED`。 |
| `foc_parameter_command_status()` | 通过同一实例生命周期、Session、IMPEDANCE 模式、精确序号和源时间，结合 RUNNING、一致快照有效感知、已确认 UPDATE 和 Pipeline 成功，报告当前观测的 `APPLIED`。后续更新可能覆盖旧观测，收据没有历史日志。 |
| 现有生命周期及独立 STOP | SET_MODE、ARM、START 通过现有请求提交，应用状态读原结果。参数 STOP 在 Foreground 调用 revoke。独立来源继续经原 inhibit API。仅隔离命令超时使用原受限清除。 |

Runtime 接口沿用原来的 H0/H1/Foreground 契约。任何同一实例的调用都按原规则串行及非重入。新模块无动态内存、全局可变状态、后台提交队列或 H0/H1 回调。参数写入不能原地重新初始化已存在实例。

实际 Host 日志中的 2.2 A 来自已初始化实例。命令 `seq=2`、源时间 **999 µs** 先得到 `ACCEPTED`，H0 在 **1,000 µs** 后得到 `APPLIED`，确认 1 次软件 UPDATE。RUNNING 静态写入拒绝。STOP 得到确认 INHIBIT，Session 1→2；原命令不能在新 Session 复活。DISABLED 暂存 1.8 A 后读回生效值仍为 2.2 A。Adapter 拒绝和无效 Sensor 场景的新 UPDATE 均为 0，后者记录 SAMPLE_INVALID（0x4）。Host 日志全程 `physical_applied=false`。
