# AT32F415 + DRV8311H 低压开环调试总结

> **现役状态（2026-09-26）**：当前 host CTest 为 `45/45 PASS`，静态/低占空比 ADC
> 链已验证；20% raw-sine 实板仍连续转动，但动态高占空比 ADC/CSA 读数在部分相位
> 不满足 KCL。`REAL_BENCH_TEST_STATUS=BLOCKED`，下一步必须用示波器同步验证 CH4、
> PWM/互补门极、SOx、真实相电流、DRV_3V3、CSAREF 和 nSLEEP。本文下方较早的
> `38/38`、`39/39`、`40/40` 等数字均为对应日期的历史快照，不是当前总数。

> 问题：低压电压开环不能流畅运行，转子卡死/失步，MCU 软件观测电流偏高。
> 当前板：COM3，12 V/1 A 电源，bench400 镜像。
> 结论状态：根因尚未唯一确认；数学、SVPWM、duty 和 CCR 路径已通过。纯电压开环运行后
> 不使用编码器反馈；当前首要证据缺口位于 CCR 之后的 TMR 引脚、DRV8311H、三相桥和电机端。

## 1. 问题定义和速度口径

本轮解决的是“正确的电压开环测试和根因定位”，不是用过小保护阈值把测试提前截断。
`5 rpm` 是闭环堵转判据中的速度条件，不是电压开环旋转目标。该电机为 7 对极：

```text
we_elec = 2π × 7 × rpm_mech / 60
30 rpm -> 21.9911 rad/s
60 rpm -> 43.9823 rad/s
```

当前软件保护包线为每相快速 `1.00 A`、任务级 `0.75 A` 持续高电流、非电压模式
`0.75 A/5 rpm/200 ms` 堵转；电压开环不使用闭环堵转判据。`0.75 A/3 s` 是最大容忍
边界，不是要求等待 3 s。12 V/1 A 电源不能替代相电流保护和人工断电。

## 2. 已完成的软件修复和验证

### 2.1 已修复/已验证

- 电流环 PI 带宽和 LPF 截止频率使用同一份有效 `currbw`，参数加载和运行时修改同步。
- `FOC_ENERGIZED_CALIB_ENABLE=0` 默认关闭带电电机/编码器校准，仅保留非带电 offset 校准。
- VBUS 无效、NaN/Inf 或除零前会阻止电压调制并进入安全路径。
- 快速 fault 在 ADC/FOC 热路径中先锁存必要 RAM 上下文，再关 PWM；ISR 不打印、不写 Flash、
  不格式化浮点、不阻塞。
- 电压模式入口在 IDLE/切入 VOLT 时同步 `theta_sim` 与 `theta_elec`；运行中不反复播种。
- bench-only fault context、FOC trace、编码器 trace、PWM/ADC map、ADC trigger 和 theta seed
  入口均为 RAM-only/IDLE-only，产品默认映射和参数未被修改。
- SVPWM 使用当前电压矢量保持实现，duty 限制在 `[0,1]`，VBUS 无效时不做除法。

### 2.2 编码器校准风险：保留，但不再作为纯开环首要直接根因

- `[实板测量]` 历史只读日志明确显示 `enc_valid=1、mech_offset=-0.124 rad、pole_pairs=7`；
  bring-up 禁止再次带电校准不等于旧校准未生效，Flash 中的旧 payload 仍在启动时加载。
- `[源码确认]` 编码器 payload 把 `phase_order、dir、mech_offset、LUT[128]、pole_pairs、calib_valid`
  作为一个耦合元组保存；当前只验证版本和 CRC，不验证电机/板号、映射、算法版本和语义范围。
- `[源码确认]` bench PWM map 会绕过已加载的 `phase_order`，`diag set enc_dir` 只改方向而不会同步
  变换或失效 offset/LUT。因此既有 map、方向和 theta0 A/B 并不是完整坐标系意义上的正交实验。
- `[静态推导/待证伪]` 校准代码以 `target-measured` 生成均值和 LUT，LUT 在运行时相加，
  但 `mech_offset` 在运行时被相减，存在 offset 符号一致性嫌疑。历史 `-0.124 rad` 在 7 对极下，
  “加/减”两种消费方式相差约 `1.736 rad_e`，与部分既有滑差同量级，但尚不能据此确认唯一根因。
- `[源码确认]` 上述风险影响一次性 `theta_sim` 播种和未来编码器闭环；进入 `CTRL_MODE_VOLT`
  后，`theta_sim` 由速度积分独立推进，固定相电压命令完全绕过编码器。因此它不能解释为持续
  反馈把开环场拉错，也不能继续排在当前板级根因第一位。

### 2.3 新收敛的功率输出边界

- `[源码确认]` 当前软件能证明到 `theta_sim→inverse Park→SVPWM→duty→TMR1 CCR`。
- `[实板未验证]` CCR 不能证明六个 PWM 引脚、DRV 的 INH/INL、三个半桥和三组线电压正确。
- `[原理图/网表确认]` MCU 到 DRV 六路输入均有明确双端点；`OUTA/OUTB/OUTC` 在网表中各自
  只列出 U4 引脚，没有列出电机连接器/焊盘组件端点。该事实不是断路证明，但暴露了输出连续性
  和顺序没有被设计资料闭合证明。
- `[源码/手册确认]` 当前 TMR1 通过 IS2 接受 TMR3 overflow 的从模式 RESET 同步；该配置与
  同源参考树不同。CCR 快照正确仍不能排除真实引脚周期截断、窄脉冲或互补时序问题。

## 5. 调试结论

### 已经可以确认

1. `[实板测量]` MCU 侧电流观测对 TMR1 CH4 compare 有可重复依赖，而且在 `we=0`
   时仍成立；旋转场不是该异常的必要条件。
2. `[无板验证][实板测量]` 电压开环内部角度、速度 ramp、SVPWM duty 和 VBUS 防护路径
   能运行到完整 bench 窗口。
3. `[实板测量]` 增加 `vq` 会提高软件观测电流，但在当前窗口内没有稳定机械同步；
   VBUS 没有同步明显塌陷。
4. `[实板测量]` 低幅 PWM/ADC map 没有出现唯一软件正常项，theta0 和 encoder direction
   也没有形成同条件重复的唯一改善。
5. `[源码确认]` 纯电压开环运行后不使用编码器反馈；编码器只影响命令入口的一次性种子，固定
   相矢量完全与编码器无关。先前把编码器排为当前首要直接根因是不成立的。
6. `[静态推导]` 完整三相的六种排列只改变相位原点或旋转方向；所有 map 都不能稳定运行时，
   更应怀疑缺相、输出畸变或功率链，而不是单纯相序。
7. `[原理图/网表确认]` MCU→DRV 输入映射在源码和网表中一致，但 DRV `OUTA/B/C` 到电机端的
   连续性、顺序和焊接没有在网表中闭合。
8. `[手册确认]` TMR1 `deadtime=0` 仅表示 MCU 没有额外插入死区。DRV8311H 在当前 strap 下
   仍有内部 VGS 握手和约 `450–760 ns` 输出死区；真实主/互补输出重叠仍未由示波器验证。

### 仍未确认

- 实际三相绕组电流是否等于 `ia/ib/ic` 软件换算值；
- TMR1/TMR3 同步后的六路 MCU 引脚是否真正输出预期互补 PWM；
- DRV 输入是否被正确接收，三只半桥是否都能在完整电周期内换相；
- `OUTA/B/C` 到电机 U/V/W 的连续性、接触和绕组端点是否正确；
- CH4 触发对应的真实 SOx 采样孔径和 CSA 建立时间；
- TMR1 主/互补实际波形是否重叠，以及 MCU 无额外死区与 DRV 内部死区组合后的物理结果；
- DRV8311H 输出、PCB 走线、电机接线和机械负载是否正常；
- encoder 的机械整圈、方向和 7 对极关系是否在真实手动基准下正确；
- 电机是否已经达到 30 rpm 机械转速。

## 6. 根因候选排序

| 优先级 | 候选 | 证据 | 不能直接下结论的原因 |
| ---: | --- | --- | --- |
| 1 | CCR 之后的实际三相输出缺失/不对称 | 数学、duty、CCR 正常；VBUS 稳定；所有 map 无唯一解；输出端设计证据未闭合 | 没有 MCU pin、INH/INL、OUTx 和线电压证据，不能细分具体坏点 |
| 2 | TMR1/TMR3 同步或互补引脚时序 | 当前启用 IS2/TMR3 overflow RESET，同源参考树无此链 | 只有配置差异，没有物理时序证据 |
| 3 | 无显式静态对齐、开环拉入动态或机械负载 | 当前播种后立即加速；窗口是拉入瞬态 | 只有真实三相输出正确时才可归因于此；裸转子惯量本身不足以解释卡死 |
| 4 | ADC/CSA/采样窗口耦合 | `we=0` 和动态 compare 转折均重复 | 是确定的测量可信度问题；纯 VOLT duty 不使用该电流，调用链不支持其为直接运动根因 |
| 独立专项 | 编码器持久化校准坐标 | payload 耦合及 offset 符号风险真实存在 | 影响一次性种子和未来闭环，不是纯开环持续失败的直接反馈根因 |

当前不允许把这些候选合并成一个“已确认根因”。

## 7. 安全停机纪律

运行中只观察预定义硬停条件；异常时不等待串口回复、不在线格式化或深度分析：

```text
发现异常或读数突变
→ 立即切断 PSU
→ 停止发送命令
→ 等待电机停止
→ 保存 fault context/trace
→ 停机后分析
```

任何接近 `0.75 A` 的测试都不能继续加压；`1.00 A` 绝对快速保护不是允许操作者等待
的目标。没有独立电流和温度时，不做更高电压或更长时间测试。
