## 生产 API、静态策略与命令所有权

- `FOC_RUNTIME_MODE_CURRENT = 0`、`VELOCITY = 1`、`POSITION = 2` 保持原值，追加 `FOC_RUNTIME_MODE_IMPEDANCE = 3`。追加字段使用现有 `foc_runtime_command.target` 联合体。旧结构初始化仍可编译，公开结构尺寸改变，二进制消费者需重编译。
- `foc_runtime_init()` 复制 `config.motion.impedance`。要求同时启用机械反馈、非零机械坐标 ID、有限正 Kt（N·m/A）和正力矩上限（N·m），刚度、阻尼、前馈的准入上限均有限且非负。检查 `Kt × motion.iq_limit_a` 可表示。原校验继续要求 `0 < motion.iq_limit_a ≤ Current.current_limit_a`。零初始化保留禁用行为，Kt 属于静态策略，任何 setpoint 均不能修改它。
- 首先在 DISABLED 且已确认 INHIBIT 时，用 `foc_runtime_publish_lifecycle_request()` 发 SET_MODE。等待原结果邮箱反映 APPLIED 和新 Session。通过 `foc_runtime_publish_impedance_command()` 发布原始序号和 Producer Timestamp，以及 `target.impedance` 的连续机械位置（rad）、速度（rad/s）、刚度（N·m/rad）、阻尼（N·m·s/rad）、前馈力矩（N·m）、机械坐标 ID 和源 Session。
- 发布前检查启用策略、字段有限性、位置域、刚度/阻尼非负及上限、前馈绝对值上限、当前模式和 Session、命令时序。拒绝发生在非活动槽写入之前，活动槽及发布水位保持。已启用阻抗的实例沿用一条跨模式、跨撤销的序号流，要求严格较新序号及不倒退的 Producer Timestamp。当前选择 IMPEDANCE 时，旧 Current/cascade 发布入口拒绝替换共享邮箱。选择旧模式后，合法的旧命令照常流入原分支。
- Foreground 写原邮箱的非活动槽并 release 发布。若写入中被 H0 STOP 或模式切换抢占，成功返回表示记录已经发布。记录保留原 Session，后续 H1/H0 仍会拒绝失效记录。独立复核识别到撤销后旧模式低序号覆盖水位的问题，已用共用发布门禁和一条以前尚未被 H0 消费的高序号回归关闭。

## H1 计算与 H0 事务

H1 acquire 读取已发布命令，从一个接受的 Sensor 快照取连续机械位置、速度、独立电角相位、捕获时间和序号。输入要求有效相位和有效同源机械数据，阻抗专用的 `mechanical_frame_id` 必须等于初始化配置及命令标识。生产者负责该 ID 所代表的轴、零位和正方向，并只在速度有效时设置它。Virtual Encoder 以 Sensor 的 `speed_valid` 和同一记录的 LPF 输出满足这项约束。

参考和反馈位置都必须在闭区间 **[−1024, +1024] rad** 内。采用 binary32、round-to-nearest 时，两次输入舍入加差分舍入的保守绝对上界为 `2⁻¹² rad ≈ 0.00024414 rad`，报告与对外契约按 0.000245 rad 向上取整。该预算仅涉及 Float32 坐标表示及减法，源编码器、零位和速度误差另计。Core 接收连续的 `target.position_rad − sample.mechanical_rad`，域内保留多圈误差且不按单圈 wrap。超范围、不同坐标 ID 或数值不合法均不发布有效阻抗目标。Sensor 整数多圈、LUT 和 H0 独立相位预测继续走原路径。

`foc_runtime_prepare_outer()` 对 IMPEDANCE 读取其专用联合体分支，调用原 `foc_impedance_step()`。DISABLED 和 READY 用通过 Core 验证的零 q 目标参与原 ARM/START 准入；RUNNING 发布 `Id=0` 和受限 `Iq`。命令序号及生产时间存入原 `foc_pipeline_command`，模式、Session、Sensor 序号及捕获时间和目标同槽发布。阻抗无积分 Trial，Velocity、Position 与 Trajectory 继续使用原 Trial 和 H0 确认机制。

H0 使用原 ADC、角度预测、目标新鲜性、模式和 Session 检查。对阻抗目标，在导入命令水位前再确认 Producer 和 Sensor 时刻均严格晚于恢复边界。当前 Session 携带恢复同戳的发布虽可记录于 Foreground，但该目标不能进入 H0 水位或用于 ARM。缺失有效目标时，H0 使用既有 INHIBIT 路径。H0 控制运算仍为原 Current PI/SVPWM 和既有 Pipeline Guard，阻抗 Core 不在 H0 重算。

- 拒绝非有限值、越域位置、无效 Kt、错模式、超参数上限、错坐标系、重复序号、过期及未来生产时刻，保持原发布和消费水位。带新 Session 的恢复同戳目标不能 ARM。撤销→切回旧模式→再回 IMPEDANCE 的流程拒绝低序号或重放，正常递增的旧模式和阻抗命令均可继续使用。
