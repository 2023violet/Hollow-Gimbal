# PARAM-01｜参数表统一来源与 TLV 存储

2026-11-24，分支 `codex/falconfoc-v2-vm01a`，基线 `c37627f`（ROM-01）。只做软件验证，没有上板。

## 结论

77 个 UART/CAN 参数现在只有一个来源 `firmware/at32f415/parameters.json`。生成器 `scripts/gen/gen_parameters.py` 输出固件表、CLI 模块、测试数据和 [参数手册](../parameters.md)，质量门禁检查生成文件是否过期。`foc_serial` 的读写改为查表，**PARAM_READ/PARAM_WRITE 的回应与改前逐字节相同**。存储改为 format 9 TLV，format 1–8 不再读取。

| 镜像 | 改前（ROM-01） | 改后 | 变化 |
| --- | ---: | ---: | ---: |
| 默认 | 97,156 B | 97,312 B | **+156 B**（参数表） |
| 带参数存储 | 101,972 B | 101,112 B | **−860 B**（去掉 8 种固定格式的编解码） |

RAM 不变。报告：[默认](2026-11-24-param-01/fwsight-default.txt)、[带参数存储](2026-11-24-param-01/fwsight-persist.txt)。

## 三步

1. **数据源与一致性**：JSON 每项写 ID、CLI 名、类型、单位、读写方式（RO / RW / 停机经 H0 / 标定修正）、上下限（常数、固件宏或活值引用）、绑定的结构体字段、是否保存、写后重算哪些增益、允许值集合。`test-foc-parameter-table` 检查表有序唯一、查找、固件宏与 JSON 数值一致、字段偏移在结构体内、CAN 波特率集合。SIL 测试 `test_parameter_table_matches_firmware` 读 ID 0–200：JSON 里的 77 个逐一核对类型、单位、可写位、标定位和常数上下限，其余 ID 全部 INVALID_ARGUMENT。第一次跑即通过，说明 JSON 与改前固件一致。CLI 原表缺的 ID 34–37、41、43、44 补上；只读 u32 参数的写入类型表补全。
2. **foc_serial 查表**：读取按组取值（串口/调参字段按偏移通用读写；启动回读、存储状态、换相与惰转、回执、转子、Kt、状态各留一个小 switch），上下限按表计算，写后重算按标志执行。原三个大 switch（265 + 156 + 139 行）和 `foc_can.c` 的本地 ID 枚举改用生成的 `FOC_PARAM_*`。
   - 线上回归：[`wire_golden.py`](2026-11-24-param-01/wire_golden.py) 在 SIL 锁步下录制 4,705 条请求/回应（两种被控对象；新鲜、写入扫描、校准后、运行中、停机后各状态读 ID 0–200；每个可写参数写下限、上限、中值、越下限、越上限、错误类型，浮点再加 NaN 和 Inf，并回读）。改前同一二进制录两次逐字节相同，改后与改前逐字节相同（SHA-256 前缀 `81517ee2b4d4b5f1` 两侧一致）。
3. **TLV 存储（format 9）**：头部 20 B（提交字、"FBP1"、格式 9、长度、序号、条目数）+ 每条 8 B（ID、类型、值）+ CRC。条目为表中 42 个保存参数，加 0xF000–0xF007 启动身份、0xF100–0xF107 标定快照，最大 488 B。解码忽略未知 ID，记录哪些参数出现过；恢复时以开机值为底，只覆盖记录里有的参数，校验与改前相同（串口上限、ID 68 不超过板子上限、Runtime 准入、标定重配置）。保存改为按编码长度写入并分块回读校验，栈上不再放第二个整记录缓冲区。
   - `test-foc-board-store` 改写：TLV 往返、未知 ID 忽略、缺项上报、重复/类型错/缺身份/保留字节非零/条目数与长度不符拒绝、format 8 记录拒绝、缺项恢复保持开机值（死区补偿 0、CAN 默认）、原有的断电撕裂、坏单元、序号回绕与恢复测试全部保留。
   - 旧测试夹具的 CAN 设置是全零（波特率 0），format 8 会悄悄改写成 1 Mbit/s；TLV 原样保存，恢复时按 CAN 设置校验拒绝，夹具已改为默认值。实际保存取自运行中的串口设置，不受影响。

## 回归

- 固件 Host 测试 17 项（含 SIL 25 项）通过；新门禁（含 `gen_parameters.py --check`）通过。
- SIL 场景 persist、calibrate-persist、swap、profile、inertia、can 都 SIL_PASS；其中 calibrate-persist、swap、inertia、can 的全部数值与 ROM-01 逐项相同。

## 局限

- 已经存有 format 1–8 记录的板子升级后会回到开机默认值，需要重新保存。目前没有出货或台架设备。
- `control_plane/` 的 Host 参数目录是另一套机制，本轮不动。
- 契约第 3 节的表格保留作设计说明，数字以生成表为准（例如单位编号 rad/s² 实为 21）。
