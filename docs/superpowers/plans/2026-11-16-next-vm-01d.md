# NEXT-VM-01d Virtual Product Acceptance Plan

## Goal

Turn the VM-01c Host Virtual device into a repeatable developer-facing
acceptance workflow with five scenarios, real load/fault timelines, CSV/JSON
exports, fixed-window quality metrics, and a standalone quick start.

## Constraints

- Modify Host simulation, Python CLI, tests and documentation only.
- Keep V1 wire format, Board1 locked policy, production PI, Runtime safety and
  ARM output permissions unchanged.
- Reuse the VM-01b Plant/Runtime/Encoder and VM-01c Serial/CLI path.
- Treat integration success and control-quality status as separate results.

## Completed tasks

1. Add fixed `current`, `velocity`, `position`, `load`, and `fault` scenario
   inputs to the existing CLI.
2. Add deterministic Plant load on/off scheduling and one-shot Encoder fault
   scheduling to the existing virtual device.
3. Export measured virtual telemetry to CSV and JSON with replay hashes and
   quality classifications.
4. Add load recovery, sensor fault response, continuous-angle and export tests.
5. Add the developer quick start and acceptance evidence.
6. Re-run simulation, sanitizer, Runtime, Board Host, Python/C CLI, formatting,
   quality gates and ARM comparison.

## Acceptance boundary

The five scenarios can be `INTEGRATION_PASS` while retaining
`CONTROL_QUALITY_FAIL`, `EXPECTED_DEGRADED`, or `NOT_MEASURED`. No category is
renamed to a product-quality pass after the run.
