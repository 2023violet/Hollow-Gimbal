# AT32F415 + DRV8311H 低压开环卡死：基于既有证据的深度根因分析

> 分析日期：2026-08-30
> 分析方式：只读复核现有源码、原理图结论和既有实板日志；本轮不运行主机测试、不构建、不刷写、不发送串口命令、不启动 PWM。
> 证据主集：`tmp/bench/20260830_103200_full_hardware_root_cause/` 及其索引的同镜像实板记录。
> bench400 ELF SHA256：`59B78D648511926F8AD47213CA35E49C0D536697BE814B1B77AF64F84E949A03`。

## 0. 是否需要完整分析流程

这件事需要走完整流程。

原因不是文档本身不可逆，而是后续判断会直接影响相序、编码器方向、电角度零点、ADC 触发位置、
驱动电压和保护策略。错误归因会把同一个问题从一个层转移到另一个层，并可能在错误电角度下继续
加压，使电机和功率级持续发热。现有证据还包含一个高风险混淆：ADC 采样窗口异常是真实的，但
它未必是纯电压开环不转的直接原因。

本轮因此停止继续试错，只完成证据分层、定量推导、反证检查和结论固化。

## 1. 真正要解决的问题

字面问题是“为什么 2804、12N14P 云台电机在低压电压开环下卡死、电流偏高”。真正的问题是：

```text
软件生成的旋转电压矢量已经推进，
但转子没有稳定跟随。

究竟是哪一层没有把“软件电角度和电压”转换成“正确方向的真实电磁转矩”？
```

正确的问题不是“下一项该把哪个参数再扫一遍”，而是把以下四条链分开：

1. **命令/数学链**：`theta_sim + vd/vq` 是否正确生成 `v_alpha/v_beta`、SVPWM 马鞍波和三相 duty；
2. **定时器/引脚链**：CCR 中的 duty 是否以正确互补关系、极性、同步时序出现在六个 MCU 引脚；
3. **DRV/功率链**：六路输入是否通过 DRV8311H、三只半桥、PCB 和绕组形成完整、平衡、连续旋转的
   三相线电压；
4. **测量/机械链**：ADC 是否可信，以及真实转矩是否足以克服摩擦、齿槽和负载。

纯电压开环不需要编码器参与持续控制。当前实现只在写入电压命令时用 `theta_elec` 播种一次
`theta_sim`，随后场角由 `we_volt_now × dt` 独立推进；固定相电压命令甚至完全不使用编码器。
因此编码器校准可能影响首次播种和未来闭环，但不能再被列为“开环持续转不起来”的首要直接根因。

现有测试长期无法收敛的主要原因，是把“软件马鞍波正确”误当成“电机端三相线电压正确”，又用
触发窗口相关的 ADC 软件电流去反推真实功率输出。真正尚未闭合的是 CCR 之后的物理链路。

## 2. 证据边界

### 2.1 本文采用的事实

- `[源码确认]` 纯 `CTRL_MODE_VOLT` 路径执行角度斜坡、反 Park、SVPWM 和 duty 输出；它会计算
  Clarke/Park 用于观测和保护，但不会让电流 PI 改写电压命令。
- `[源码确认]` 编码器只在 IDLE/切入 VOLT 时用于一次性播种 `theta_sim`；进入运行后不会作为
  电压开环反馈变量。`foc_cmd_phase_volt()` 使用显式相位，完全与编码器无关。
- `[源码确认]` 电压命令进入 IDLE 时，`theta_sim` 已同步到当前 `theta_elec`，bench 下再叠加
  RAM-only `theta_seed_offset_rad`，并将 `we_volt_now` 清零。早期“首次命令仍从零角开始”的
  软件缺陷已经修复。
- `[源码确认]` `theta_elec=(theta_mech_raw-mech_offset)×pole_pairs`；`mech_offset`、`dir`、
  `phase_order` 和 128 项 LUT 作为同一个编码器校准 payload 保存并在启动时恢复。
- `[实板测量]` 历史只读基线明确显示 `enc_valid=1、mech_offset=-0.124 rad、pole_pairs=7`；
  后续同板日志持续显示 `enc_valid=1`。当前 bring-up 固件虽然禁止再次执行带电编码器校准，
  但这不等于“运行时没有校准数据”：Flash 中的旧校准仍然会生效。最终同镜像日志没有再次
  输出 offset、dir、phase_order 和 LUT，因此不能断言当前有效校准元组的精确内容。
- `[源码确认]` 软件 PWM 映射为 `A→TMR1 CH3、B→CH2、C→CH1`；ADC 注入 rank 为
  `VBUS→IC→IB→IA`。
- `[源码确认]` TMR1 约 20 kHz 中心对齐，bench FOC step 约 5 kHz；ADC 四 rank 顺序转换，
  默认 CH4 compare 为 3740。
- `[源码确认]` 当前 TMR1 还配置为由 `IS2` 触发的从模式复位；AT32F415 官方参考手册给出的
  TMR1 `IS2` 来源为 TMR3，而当前 TMR3 以约 20 kHz overflow 输出主触发。该同步关系与同源
  FalconFoc 参考树的“独立 TMR1、ARR=7499、deadtime=15”不同，尚未由引脚波形证明其物理效果。
- `[原理图/网表确认]` MCU 到 DRV 的 `INHA/INLA...INHC/INLC` 网络有双端点；但网表中的
  `OUTA/OUTB/OUTC` 每个只列出 U4 自身引脚，没有列出电机连接器或焊盘组件端点。它不能证明
  实板断路，但说明现有设计资料没有闭合证明“DRV 输出—电机端”的连续性与顺序。
- `[实板测量]` 相同 bench400 镜像下，VBUS 在主要试验中约为 `11.83–11.93 V`，未随软件
  电流上升同步塌陷。
- `[实板测量]` `vq=1.0–2.5 V` 时，`theta_sim` 和 `we_volt_now` 均推进，软件电流包络随电压
  总体上升，但编码器没有形成稳定同步。
- `[实板测量]` CH4 compare 从 1874 变到 2300 以后，软件电流读数出现可重复阶跃；该现象在
  `we=0` 固定电压矢量下仍可复现。
- `[实板测量]` 低幅 `0.05 V` 的 36 组 PWM/ADC map 没有唯一优胜，六向固定矢量也没有低幅
  单相饱和。
- `[实板测量]` 相位偏置与 encoder direction A/B 没有得到同条件、可重复的唯一优胜。

### 2.2 本文不采用的“证明”

- 软件 ADC 电流不是独立相电流计读数；
- 软件 CCR/duty 不是 DRV 输入或半桥输出波形；
- `theta_elec` 不是天然等同于转子永磁体 d 轴；
- VBUS 稳定不能证明三只半桥都正常；
- 低幅 map 无唯一优胜不能证明默认物理相序正确；
- 400 ms 预算不能证明电机已在 30 rpm 稳态连续运行；
- 主机数学测试不能证明真实电机、DRV8311H、采样孔径、死区或热稳定性。

不同 ELF 哈希的历史日志不作为同条件重复；它们只能提供历史背景。

## 3. 暴露假设

| 隐含假设 | 当前状态 | 若不成立的后果 |
| --- | --- | --- |
| 正确的 CCR 等价于正确的 MCU 引脚波形 | **未证实，首要关键假设** | TMR 同步、极性、互补输出或引脚复用异常可让日志正确而物理输入错误 |
| 六路 DRV 输入能形成三个健康半桥输出 | **未证实，首要关键假设** | 缺相、弱桥臂、焊接/PCB/DRV 损坏会直接造成非旋转磁场、卡死和高电流 |
| `OUTA/OUTB/OUTC` 与电机三端连续且绕组健康 | **设计资料未闭合，首要关键假设** | 网表无电机输出端点；任一断路、错接或绕组异常都能使算法正确但电机不转 |
| 仅交换三相排列可以修复“完全不转” | **通常不成立** | 三个健康相的完整排列只改变相位原点或旋转方向；若所有排列均失败，更应怀疑缺相/波形畸变而非顺序本身 |
| MCU ADC 电流峰值接近真实绕组电流 | **已被触发敏感性削弱，关键假设** | 不能用当前数值推导真实转矩，也不能据此断言“电压已足够”或“真实电流过高” |
| 转子处于自由、低负载状态 | 日志没有定量机械证明 | 若总惯量、摩擦或卡滞远高于裸电机，拉入失败可由机械链主导 |
| 400 ms 测试包含 30 rpm 稳态 | **不成立** | `we_now` 尾值仅约 `16.7–18.2 rad/s`，低于目标 `21.99 rad/s`；既有试验是加速/拉入瞬态，不是稳态转速验收 |
| VBUS 稳定代表功率级正常 | 不成立 | 它只能弱化整机输入电源塌陷，不能排除单桥臂、焊接、DRV 输出或局部地回路异常 |
| 编码器校准错误会持续破坏纯电压开环 | **不成立** | 运行后 `theta_sim` 独立推进；编码器只影响一次性种子，固定相矢量连种子也不使用 |

会直接推翻根因排序的两个假设是：

1. 电机端的三组线电压是否真的平衡、相差 120°，并按命令连续旋转；
2. 若实际三相线电压正确，启动前是否存在足够的静态对齐时间和机械拉入裕量。

## 4. 已有数据的定量再解释

### 4.1 这些试验不是“稳定 30 rpm”试验

7 对极、30 rpm 机械速度对应：

```text
we_target = 2π × 7 × 30 / 60 = 21.99 rad/s
```

默认电气加速度为 `60 rad/s²`，从零达到目标需要：

```text
t_ramp = 21.99 / 60 ≈ 0.367 s
```

但完整窗口日志的 `we_now` 尾值约为 `16.7–18.2 rad/s`。按同一斜坡反推，有效推进时间约
`0.279–0.303 s`。所以这些数据描述的是**启动拉入过程**，而不是达到 30 rpm 后的稳态。

在约 0.30 s 内，模拟电角位移约为：

```text
Δθ ≈ 0.5 × 60 × 0.30² ≈ 2.7 rad
```

这与 1–2 V 日志的 `theta_sim` 变化量大致一致，但小于一个完整电角周期，更远小于一机械圈。
因此当前数据足以证明“旋转场有推进、转子发生部分响应或滑差”，不足以证明稳定同步能力。

### 4.2 单纯“电压太低”不能很好解释 2–2.5 V 结果

当前参数：

```text
Rs = 2.55 Ω
Ls = 0.86 mH
flux = 0.0035 Wb
p = 7
```

电气时间常数：

```text
τe = Ls / Rs ≈ 0.337 ms
```

它远短于约 300 ms 的启动窗口，说明电气暂态不会持续整个试验。30 rpm 目标处的反电动势近似：

```text
E ≈ we × flux ≈ 21.99 × 0.0035 ≈ 0.077 V
```

相对于 `1–2.5 V` 命令很小。忽略坐标误差和 PWM 非理想，电阻近似电流为：

| `vq` | `vq/Rs` | 扣除目标速度反电动势后的量级 |
| ---: | ---: | ---: |
| 1.0 V | 0.392 A | 约 0.362 A |
| 1.5 V | 0.588 A | 约 0.558 A |
| 2.0 V | 0.784 A | 约 0.754 A |
| 2.5 V | 0.980 A | 约 0.950 A |

软件 ADC 观测到的包络与这一量级并非完全矛盾。电机转矩常数近似：

```text
Kt = 1.5 × p × flux ≈ 0.03675 N·m/A
```

若真实 q 轴电流达到 `0.5–0.75 A`，预期电磁转矩约 `0.018–0.028 N·m`，已经接近资料中的
约 `0.03 N·m` 量级。对于真正自由、低负载的转子，“2.5 V 仍只是正常转矩不足”不是最强解释。

但这段计算有一个决定性条件：软件观测必须是真实电流，并且电流必须主要位于产生正向转矩的
q 轴。当前两项都没有被独立证明。因此它能削弱“纯粹电压太低”，不能证明电机已经产生上述转矩。

### 4.3 现有数据更像“转子部分跟随后失去同步”

同镜像完整窗口中：

| `vq` | `theta_sim` 变化 | `theta_elec` 变化 | 尾部相位差量级 |
| ---: | --- | --- | ---: |
| 1.0 V，第 1 次 | `3.395→6.115` | `3.398→4.789` | 约 `+1.33 rad` |
| 1.0 V，第 2 次 | `4.807→1.240` | `4.807→5.751` | 约 `+1.77 rad` |
| 1.5 V | `5.703→2.143` | `5.710→0.571` | 约 `+1.57 rad` |
| 2.0 V | `0.468→3.220` | `0.462→2.244` | 约 `+0.98 rad` |

`[静态推导]` 编码器角度并非完全冻结；转子有部分跟随，但软件场领先并形成较大滑差。这个形态
比“SVPWM 完全没有运行”更接近以下三种情况：

1. 绝对电角零点或方向错误，实际转矩分量从一开始就不是最大正 q 轴；
2. 物理相序/功率输出与软件坐标不一致；
3. 启动负载或拉入条件超过开环同步能力。

尾部差值只是软件角度与编码器计算角度之差，不是已经校准的转矩角，不能直接当成负载角。

### 4.4 裸转子惯量不是一个足够强的解释

30 rpm 对应机械角速度约 `3.142 rad/s`。在 `0.367 s` 内达到该速度，机械角加速度约为：

```text
alpha_mech ≈ 3.142 / 0.367 ≈ 8.56 rad/s²
```

按电机资料中的转子惯量 `J=3.7e-6 kg·m²`，仅用于加速裸转子的惯性转矩为：

```text
T_inertia = J × alpha ≈ 31.7 µN·m
```

即使把总惯量放大 100 倍，惯性转矩也只有约 `3.2 mN·m`。相比前文由 `0.5 A` 推导的约
`18 mN·m` 电磁转矩量级，**裸转子惯量本身不足以解释卡死**。机械链仍可成为根因，但必须是
静摩擦、轴承/线束卡滞、外部负载或实际 q 轴转矩根本没有建立，而不是“2804 转子惯量天然太大”。

## 5. ADC 触发异常：确认存在，但不应被写成开环主根因

### 5.1 可以确认什么

`[实板测量]` 在同一镜像、同一命令下，CH4 compare 的改变使软件电流读数出现可重复转折：

- `1874`：三相约 `0.01–0.02 A`；
- `2300`：B 相约 `0.26 A`；
- `2812/3740`：A/B 相约 `0.24–0.26 A`；
- 该转折在 `vq=1 V、we=0` 时仍存在；
- VBUS 没有同步下陷，也没有 software fault。

这足以确认：

```text
ADC_MEASUREMENT_WINDOW=REPRODUCIBLY_TRIGGER_DEPENDENT
```

它支持低侧导通窗口、SOx/CSA 建立时间、四 rank 顺序转换和中心对齐触发相位存在耦合。

### 5.2 为什么低 compare 的“小电流”反而可能是无效读数

DRV8311H 的 SOx 来自低侧电流感测。只有对应低侧器件处于有效导通并完成建立时，SOx 才能代表
该相电流。ADC 四 rank 不是同时采样，而是依次完成约 4.27 us 的转换。CH4 触发后，计数器仍
继续变化，后续 rank 可能跨过某一相的 PWM 边沿。

因此：

- 早触发点读到接近中点，不等于真实电流很小，也可能是低侧尚未形成有效感测窗口；
- 晚触发点读到较大值，不等于它必然正确，但它更可能覆盖到低侧导通电流；
- 不同相的 rank 顺序不同，能自然产生“某一相先发生阶跃”的现象。

默认 `CCR4=3740` 在高 duty 边界下，最后一个注入 rank 与低侧边沿的余量按现有审计约只有
`0.5 us` 量级，小于或接近 DRV 传播/建立的不利边界，因此默认点也不能仅凭软件数据宣称正确。

静态 `vq=1 V、we=0` 日志还提供了比“读数随 trigger 变”更具体的几何证据。该工况的 duty
稳定在约 `A/B/C=0.532/0.430/0.570`，对应：

```text
CH1(C) ≈ 2138
CH2(B) ≈ 1610
CH3(A) ≈ 1995
```

`compare=1874` 位于三个相 compare 之间，而 `2300/2812/3740` 全部高于三个相 compare。
在当前中心对齐 PWM Mode A 和 CH4 有效边沿约定下，这意味着 1874 与 2300 之间恰好跨越了
“部分相已经切换”到“共同低侧状态”的 PWM 几何边界。实板读数又恰好在 2300 开始出现 B 相
阶跃、在 2812 后出现 A/B 两相阶跃。该一致性显著加强了以下判断：

```text
trigger 阶跃主要是 PWM 开关状态、低侧 Sense-FET 可见性、CSA 建立和顺序 rank 共同造成的，
不是随机 ADC 噪声。
```

这仍不能从软件日志单独选出“正确 compare”，因为 trace 中的 `TMR1 CVAL` 是 ISR/FOC 后续
快照，不是每个 rank 的模拟采样瞬间；但它已经足以否定“1874 数值小，所以 1874 更正确”。

### 5.3 它为什么不是纯电压开环的直接闭环变量

纯 `CTRL_MODE_VOLT` 的实际控制路径是：

```text
theta_sim + vd/vq
  → inverse Park
  → SVPWM
  → TMR1 duty
```

ADC 电流在该模式中用于观测、故障判断和日志；电流 PI 不参与输出。既有完整窗口没有触发会打断
输出的过流 fault。因此即使 ADC 窗口错误，它也不会在当前路径里直接把 duty 算错。

结论是：

- **ADC/CSA 采样窗口是必须在进入电流闭环前解决的确定性问题；**
- **它可能让我们误判真实电流和转矩；**
- **但现有调用链不支持“它单独造成纯电压开环旋转场卡死”的说法。**

把采样点改到读数最小的位置，只会让日志更好看，不能证明物理电流更小，更不能修复坐标或功率链。

## 6. “不知道自己不知道”的盲区

### 6.0 纠偏：编码器风险不等于纯开环主根因

以下 6.1–6.3 记录的持久化校准、方向和 offset 符号风险仍然是有效的软件质量问题，未来进入
编码器 FOC 闭环前必须解决；但它们在本问题中的因果地位需要降级：

```text
写入 VOLT 命令时：theta_elec -> 一次性 theta_sim seed
进入 RUNNING 后： theta_sim += we_volt_now * dt
输出 duty：        theta_sim + vd/vq -> inverse Park -> SVPWM
```

所以编码器可以改变首次矢量相位，却不会持续把旋转场“拉回错误角度”。对于自由转子，一个健康的
三相功率级即使从任意初相开始，也应先产生某个静态吸附方向；合理的对齐等待后再旋转即可完全
脱离编码器。若 1–2.5 V 的完整场仍只卡死/尖叫，编码器不是最先解释的对象。

### 6.1 绝对电角零点不是编码器读数本身

编码器能稳定返回机械角，只能证明传感器在测位置。FOC 需要的是转子磁链 d 轴相对于软件 A/B/C
坐标的角度。二者之间还包含：

```text
有效电角 = 方向符号 × 极对数 × 编码器机械角
           - 磁轴零点偏移
           + 物理相序/绕组定义带来的坐标变换
```

当前带电编码器校准被禁止，主证据没有执行新的 `encoff`；但 Flash 中已有 `enc_valid=1` 的旧校准
并正在生效。真正的问题因此不是“offset 为默认零”，而是**现有 offset/LUT/dir/phase_order 从何而来、
是否由当前算法和当前相序生成、符号是否自洽**。没有装配磁轴证据，也没有校准 provenance，
“已经把 `theta_sim` 对齐 `theta_elec`”只修复了软件入口不一致，并没有证明它对齐真实转子磁轴。

### 6.2 现有 bench A/B 把一个校准元组拆开了

Flash 中的编码器 payload 不是只有 offset，而是：

```text
{ LUT[128], mech_offset, pole_pairs, phase_order, dir, calib_valid }
```

启动恢复只验证存储 magic、结构版本、长度和 CRC；当前没有看到以下语义检查：

- offset/pole_pairs 的有限性和范围；
- `phase_order/dir` 枚举合法性；
- LUT 幅值和连续性；
- 校准对应的电机、板号、PWM 映射和算法版本；
- 校准元组是否与当前 firmware 的坐标约定兼容。

更关键的是，bench 固件的 `pwm_out_set_duty()` 始终使用 RAM `_bench_pwm_map`，不使用刚从 Flash
恢复的 `motor->hw_config.phase_order`。默认 map0 恰好等价于产品 ABC，但如果旧校准曾把
`phase_order` 判为 ACB，bench map0 就已经把校准元组拆开。`diag map show` 只显示 bench map，
不会显示持久化 phase order。

同样，`diag set enc_dir` 只改 `config->dir`，不会变换或作废 `mech_offset/LUT/calib_valid`；
`theta0` 只改启动种子，也不会修正 LUT 索引方向。于是先前的 PWM map、encoder direction 和
theta0 扫描只在 Shell 参数层面“单变量”，在真实坐标层面并不正交。

这解释了为什么不同方向/offset 能改变局部响应，却没有稳定唯一优胜：实验可能一直在组合
“新 dir 或新 map + 旧 offset/LUT”。所以既有“相位没有唯一优胜”和“map 没有唯一优胜”不能
合并成“坐标链已排除”。

### 6.3 编码器校准均值存在符号一致性嫌疑

校准代码的局部误差定义为：

```text
pos_err = pr_set - measured_pos
mean = average(pos_err)
LUT_local = pos_err - mean
```

LUT 在运行时是**加到**方向修正后的 raw count 上；这与“误差=目标-测量”相符。但校准结束又执行：

```text
mech_offset = mean
```

运行时却使用：

```text
theta_mech = measured_pos - mech_offset
```

在最简单的零偏模型 `measured=true+bias` 下，`mean=target-measured≈-bias`，正确修正应是
`measured+mean`；当前实现变成 `measured-mean`。因此存在**校准均值符号与运行时减法相反**的
代码级嫌疑。

历史值 `mean/mech_offset=-0.124 rad` 若按上述模型解释：

```text
单次运行时角移量       = -offset × 7 = +0.868 rad_e
相对正确加法的差异量   = -2 × offset × 7 = +1.736 rad_e ≈ 99.5°
```

这个 `1.736 rad` 与既有完整窗口末端约 `0.98–1.77 rad` 的场—编码器滑差量级高度接近。它是
非常值得重视的数值吻合，但仍标记为 `[静态推导/待证伪]`：校准使用 q 轴电流拖动，`pr_set`、
物理磁轴和相序之间可能还含固定相位约定，不能仅凭代数就宣布唯一根因。

当前没有针对 `foc_calib_enc.c` 的完整 host 数学契约测试，尤其没有“注入已知 encoder bias，
校准后电角度回到已知磁轴”的端到端测试。这使该符号风险长期没有被自动门禁捕获。

### 6.4 真实功率输出仍是黑箱

软件知道 CCR，板上 ADC 知道 SOx；两者之间仍有 DRV 输入逻辑、半桥、焊接、连接器和绕组。
一个桥臂弱导通、单相连接不良、相序与命名不一致，都可能让软件数学正确但真实旋转磁场错误。
VBUS 稳定并不能排除这些局部故障。

### 6.5 MCU deadtime=0 不等于功率级 deadtime=0

原理图中的 `MODE/SLEW/GAIN` 均通过 47 kΩ 下拉，DRV8311H 因此工作在 6x PWM、约 75 V/µs、
0.5 V/A 的硬件配置。DRV8311H 手册明确说明其内部通过 VGS handshake 防止上下管交叉导通；
在 12 V、47 kΩ SLEW 条件下：

```text
内部输出 deadtime：典型 450 ns，最大 760 ns
传播延迟：典型 650 ns，最大 1100 ns
最小输出脉宽：500 ns
CSA ±1% 建立时间：1 µs
```

因此 TMR1 `deadtime=0` 的准确含义是“MCU 没有额外插入 deadtime”，不是“DRV 半桥零死区直接
贯通”。这削弱了“deadtime=0 必然导致卡死/高流”的判断。

但内部时序会造成电流方向相关的 duty 畸变。20 kHz 载波周期为 `50 µs`，内部 deadtime 占
`0.9–1.52%` 周期；传播延迟占 `1.3–2.2%`。而：

```text
0.05 V / 12 V ≈ 0.42% duty
0.25 V / 12 V ≈ 2.08% duty
1.00 V / 12 V ≈ 8.33% duty
```

所以 `0.05 V` 映射矩阵的命令分辨率低于驱动内部时序尺度，无法有效区分相序；`0.25 V` 仍与
时序误差同量级。该效应能解释低幅实验缺乏区分力和低速转矩非线性，但单独不足以解释 1–2.5 V
下仍无法同步。

### 6.6 机械条件没有进入证据链

裸转子惯量很小，但云台结构、轴承预紧、线束扭力和外部负载可能远大于电机本体。现有日志没有
统一的转子起始机械角、负载转矩或手动阻力记录。因此不能严格排除机械链，也不能把所有滑差都
归为控制错误。

## 7. 最强的四个分析方向

### 方向 A：实际三相功率输出不完整或不对称——当前最强直接根因类别

**最强论证**

- `[事实]` 已确认的是数学、duty 和 CCR，不是六个 PWM 引脚及 `OUTA/OUTB/OUTC` 线电压；
- `[事实]` 网表能闭合 MCU 到 DRV 输入，却没有给 `OUTA/OUTB/OUTC` 列出第二个组件端点；
- `[事实]` 某个静态矢量能形成近似 KCL 自洽的两相电流，只证明部分桥臂/绕组能够导电，不证明
  三个桥臂在六个扇区中都能正确换相；
- `[事实]` 六种健康三相排列只会改变相位原点或旋转方向，不能解释所有排列都无法形成稳定旋转；
- `[推测]` 某个 MCU 引脚、互补对、DRV 半桥、焊接/PCB、输出焊盘、电机引线或绕组端点缺失/弱化，
  会把正确马鞍波变成脉动或单相磁场，直接造成卡死、尖叫和高铜耗。

**何时它是最优解释**

当软件角度和 CCR 连续、VBUS 不塌陷，但所有开环参数/相序都不能得到稳定旋转时。它与当前现象
匹配度最高。

**代价与风险**

现有软件日志不能继续细分到底是 MCU pin、DRV 输入、半桥、PCB 还是电机端。把 CCR 当作物理
输出继续调算法，会掩盖缺相并增加局部桥臂和绕组发热。

**本文排序**：第 1；对“问题位于 CCR 之后的物理输出链”中高置信度，对具体坏点仍低置信度。

### 方向 B：TMR1/TMR3 同步或互补输出的引脚时序与寄存器值不等价

**最强论证**

- `[事实]` 当前 TMR1 为中心对齐 ARR=3749，同时启用从模式 RESET、输入 IS2；TMR3 ARR=7499
  并以 overflow 作为主触发，二者名义周期同为约 50 µs；
- `[事实]` AT32F415 手册规定 TMR1 的 IS2 来自 TMR3；因此 TMR1 会受 TMR3 overflow 同步复位；
- `[事实]` 同源 FalconFoc 参考树使用独立 TMR1、ARR=7499、deadtime=15，没有该 TMR3 复位链；
- `[推测]` 复位边界、CCR buffer 更新、计数方向或互补输出在真实引脚上可能产生日志看不到的窄脉冲、
  周期截断或相间不同步，而 CCR 快照仍完全正确。

**何时它是最优解释**

当三个 DRV/绕组硬件端点连续，但 MCU 六路引脚并没有稳定复现预期互补 PWM 时。

**代价与风险**

这只是源码差异和手册时序共同给出的候选，不足以直接宣布 TMR reset 配置错误。贸然删除同步或照搬
参考树可能破坏 ADC 触发节拍；必须先在文档中保持 `UNVERIFIED`。

**本文排序**：第 2，属于“软件寄存器到真实引脚”的边界候选。

### 方向 C：开环启动缺少显式静态对齐和拉入阶段

**最强论证**

- `[事实]` 纯开环不需要编码器，但需要选择一个定子矢量、等待转子吸附，再从该已知相位缓慢推进；
- `[事实]` 当前代码用编码器角度播种后立即开始 `we_volt_now` 斜坡，没有独立的静态 alignment dwell；
- `[事实]` 现有 400 ms 窗口大部分处于加速瞬态，开环一旦失步没有反馈机制重新捕获；
- `[事实]` 裸转子惯性加速转矩约 `31.7 µN·m`，远小于健康三相在 1–2.5 V 下应具备的转矩量级；
- `[推测]` 若有明显齿槽、线束、轴承预紧或外部负载，立即旋转的场可能在对齐前就拉出同步。

**何时它是最优解释**

仅当实际三相线电压已知完整、平衡且方向连续时。此时应把启动流程改成“无编码器静态对齐→保持→
受控斜坡”，而不是继续修编码器 offset。

**代价与风险**

它可以解释拉入失败，但难以单独解释在自由转子、1–2.5 V 下始终不能得到任何正确旋转。如果功率级
缺相，增加对齐时间只会延长发热。

**本文排序**：第 3。

### 方向 D：ADC/CSA 采样窗口异常——确定的测量问题，但不是首要运动根因

**最强论证**

- `[事实]` compare 转折在静态和动态条件下均可重复；
- `[事实]` 低侧 CSA 有明确有效导通窗口，四 rank 又是顺序采样；
- `[事实]` 纯 VOLT 路径不使用电流 PI，且相关试验没有因 fault 中断；
- `[推测]` 当前读数中至少一部分是开关状态/采样孔径的函数，而不只是绕组电流的函数。

**何时它是最优解决方向**

在任何准备进入电流闭环、校准电机参数或依赖软件电流保护定量值之前。它也是恢复“软件电流可相信”
这一前提的必要工作。

**代价与风险**

把“读数更小”当作“采样更正确”会制造假修复。即使最终修好测量链，电角参考或功率链问题仍可能
独立存在。

**本文排序**：测量链第 1；对纯电压开环不转的直接因果排序较低。

## 8. 真正的分歧点

各方案的核心分歧不是某个 compare、编码器 offset 或电压数值，而是：

```text
电机端 U-V、V-W、W-U 三组实际线电压，
是否与软件 CCR 对应、幅值平衡、相隔 120°并连续旋转？
```

这是只改变一个假设就会翻转结论的关键：

- **若答案是“否”**：根因位于 TMR 引脚、DRV 输入/半桥、PCB、接线或绕组；编码器、PI、ADC
  trigger 和电机参数都不是首要修复点；
- **若答案是“是”**：才把首要候选转向无编码器静态对齐、启动斜坡、机械阻力和电机参数。

第二个独立问题是：

```text
当前软件观测到的电流，是否是真实相电流？
```

ADC trigger 证据已经说明它不能被默认相信。即使它不直接进入 VOLT duty 计算，也会污染对
“转矩已足够”的判断。

## 9. 当前可以和不可以下的结论

### 9.1 可以确认

1. `[源码确认][无板验证]` 纯电压开环内部数学链能推进角度并输出有限 duty；电流 PI 不是该路径
   的直接控制变量。
2. `[实板测量]` 板上软件场实际推进，但转子没有建立稳定同步；这不证明编码器参与了持续控制。
3. `[实板测量]` VBUS 在短窗口内没有明显塌陷，整机输入欠压不是当前最强根因。
4. `[实板测量]` ADC/CSA 观测对 CH4 compare 有可重复依赖，当前软件电流不能直接等同于独立
   真实相电流。
5. `[静态推导]` 既有“30 rpm”数据是拉入/加速瞬态，不是达到目标后的稳态运行证明。
6. `[源码确认]` 纯电压开环运行后由 `theta_sim` 独立推进；编码器只影响一次性入口种子，固定
   相矢量完全不依赖编码器。因此编码器校准不是当前持续不转的首要直接根因。
7. `[静态推导]` 完整三相的任意相排列仍会产生正转或反转旋转场；“所有 map 都失败”更支持
   缺相/畸变/功率链异常，而不是单纯相序错误。
8. `[原理图/网表确认]` MCU→DRV 输入网络闭合，但 `OUTA/B/C` 在网表中没有电机端第二组件端点；
   物理输出连续性和顺序没有被设计资料证明。
9. `[手册确认]` TMR1 deadtime=0 不代表 DRV8311H 没有内部死区；但内部时序足以淹没 0.05 V
   低幅映射实验的区分力。
10. `[源码/手册确认]` 当前 TMR1 受 TMR3 overflow 复位同步，与同源参考配置不同；CCR 正确
    仍不能证明六路引脚时序正确。
11. 继续盲扫电压、offset、map 或 trigger 不会自动生成缺失的跨域证据，且可能增加热损伤。

### 9.2 不能确认

1. 不能确认默认 PWM 物理相序正确；
2. 不能确认 TMR1/TMR3 同步后的六路实际引脚时序和互补关系正确；
3. 不能确认 DRV 三个半桥和电机三相绕组在动态下均正常；
4. 不能确认 `OUTA/B/C` 到电机端的连续性、顺序和接触质量；
5. 不能确认 1874、2300、2812 或 3740 中任一点就是正确采样窗口；
6. 不能确认软件峰值是实际相电流，也不能据此计算实际 q 轴转矩；
7. 不能确认无编码器静态对齐后，电机仍无法拉入；
8. 不能确认电机在无负载机械条件下仍无法拉入；
9. 编码器校准坐标仍未验证，但不能把它写成纯电压开环持续失败的直接根因；
10. 不能确认唯一坏点，不能写入 `OPEN_LOOP_ROOT_CAUSE_STATUS=IDENTIFIED`。

## 10. 缺失的关键证据

当前最缺的是能连接“正确 CCR”与“真实电机输入”的物理边界证据：

```text
软件 theta/duty/CCR
↔ 六个 MCU PWM 引脚
↔ DRV INH/INL 与 OUTA/B/C
↔ U-V、V-W、W-U 三组线电压
↔ 绕组连续性和真实转子响应
```

没有这条证据，马鞍波、CCR 和板上 ADC 都处在同一软件观测侧，无法证明功率级。编码器校准端到端
不变量仍值得单独补齐，但它属于未来闭环和软件质量，不再是本轮开环主根因的第一证据。

本文只记录证据缺口；遵照本轮要求，不执行任何新增测试，也不把它改写成当前阶段的实机计划。

## 11. 最终结论

### 11.1 这件事是否值得做

**值得做，而且当前最正确的动作是停止继续盲测，改为冻结证据和修正问题定义。**

不应该放弃项目，也不应该把更多电压、更多 offset 或更多 compare 扫描当作默认下一步。当前需要
改的是根因分析方法：将“运动根因”和“电流测量可信度”作为两个并行问题，而不是用一个解释另一个。

### 11.2 当前最强结论

```text
PRIMARY_DIRECT_HYPOTHESIS=
  ACTUAL_THREE_PHASE_OUTPUT_ASYMMETRY_OR_MISSING_LEG
  (TMR pin / DRV input / half bridge / PCB / motor lead or winding)

ADC_MEASUREMENT_WINDOW=REPRODUCIBLY_TRIGGER_DEPENDENT
ADC_ISSUE_IS_DIRECT_OPEN_LOOP_CAUSE=NOT_SUPPORTED_BY_CALL_PATH

OPEN_LOOP_MATH_AND_DUTY_PATH=PASS
OPEN_LOOP_ENCODER_ROLE=ENTRY_SEED_ONLY_NOT_FEEDBACK
ENCODER_CALIBRATION_FRAME=UNVERIFIED
TIMER_PIN_DRV_OUTPUT_PATH=UNVERIFIED
PHYSICAL_LINE_TO_LINE_VOLTAGE=UNVERIFIED
MOTOR_PHYSICAL_OPERATION=UNVERIFIED
OPEN_LOOP_ROOT_CAUSE_STATUS=UNRESOLVED
REAL_BENCH_TEST_STATUS=BLOCKED
```

首要候选不再是编码器。当前最一致的解释是：**正确的软件旋转矢量在 CCR 之后没有完整地到达三相
电机端**。这可以是 TMR 同步/引脚、DRV 六路输入、某个半桥、PCB/焊接、电机引线或绕组问题。
现有资料只能把范围收敛到这一边界，不能诚实指定具体元件。

编码器校准元组确有来源和符号风险，但纯开环运行后不依赖编码器反馈；它应作为闭环前专项修复，
不能继续覆盖当前板级输出问题。

### 11.3 最大风险

最大风险是把正确的马鞍波、duty 和 CCR 误认为电机端已经获得正确三相电压，然后继续改编码器、
PI、ADC trigger 或升压。若真实问题是缺相、窄脉冲、弱桥臂或接触不良，升压只会把更多能量
集中到仍在工作的桥臂和绕组，造成发热甚至损坏。

### 11.4 最缺的关键证据

最缺的关键证据是三相实际线电压与软件 CCR 的对应关系，尤其是三个互补 PWM 对、DRV 输入和
`U-V/V-W/W-U` 在完整电周期内是否平衡连续。当前“不再测试”的约束意味着本轮只能明确指出这个
证据缺口，不能从软件日志虚构具体坏点。

### 11.5 今天可以执行的最小一步

今天的最小一步就是本文：冻结当前证据集、停止继续升压/扫参，并把边界重新定义为：

```text
已证明：theta_sim -> inverse Park -> SVPWM -> duty -> CCR
未证明：CCR -> MCU 六路引脚 -> DRV -> 三相线电压 -> 绕组
```

本轮同时完成了三项只读收敛：

1. 将编码器从纯开环首要直接根因降级为一次性播种/未来闭环问题；
2. 将 ADC trigger 问题保留为独立测量可信度问题；
3. 将 TMR1/TMR3 同步差异、DRV 输出链和网表输出端点缺口列为首要审计边界。

本轮不做任何测试，不修改任何控制参数、相序、ADC trigger、保护阈值或电机参数。

### 11.6 置信度

- 对“ADC 触发依赖真实存在，但不是纯电压开环的直接闭环根因”：**高置信度，约 90%**。依据是
  静态/动态重复数据与 `CTRL_MODE_VOLT` 调用链相互独立支持。
- 对“编码器不是纯电压开环持续失败的直接反馈根因”：**很高置信度，约 95%**。依据是运行时调用链
  明确由 `theta_sim` 独立推进，固定相矢量完全绕过编码器。
- 对“正确马鞍波/CCR 不能证明真实三相线电压”：**很高置信度，约 98%**。这是软件—硬件边界
  的直接逻辑结论，且现有证据没有观测该边界。
- 对“CCR 之后存在缺相或三相输出不对称，是当前最强根因类别”：**中高置信度，约 70%**。支持
  证据是算法和 CCR 正常、VBUS 稳定、所有软件映射无唯一解、网表输出端点未闭合、1–2.5 V 仍不能
  建立旋转；降低置信度的因素是没有实际线电压/引脚波形，无法排除启动拉入和机械问题。
- 对“TMR1/TMR3 复位同步就是具体根因”：**低到中等置信度，约 40%**。配置差异真实存在，但尚无
  物理时序或寄存器事件证据证明它破坏了输出。
- 对“现在不能诚实确认唯一根因，继续盲测不应作为默认策略”：**高置信度，约 90%**。依据是多个
  CCR 后候选对同一软件日志具有等价解释，且既有 map/phase 扫描没有观测真实线电压。

综合结论是：**对“问题不应继续归咎编码器、PI 或 SVPWM 数学”有高置信度；对“问题位于 CCR
之后的实际三相输出链”有中高置信度；对具体是 TMR pin、DRV、PCB、接线还是绕组，现有证据不足。**
