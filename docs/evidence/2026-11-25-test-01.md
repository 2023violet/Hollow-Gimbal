# TEST-01｜Board1 SIL 按场景拆分并行

2026-11-25，分支 `codex/falconfoc-v2-vm01a`，基线 `10858bc`（RES-01）。只改测试注册方式和矩阵并行度，固件、ARM 镜像和测试内容都不变。

## 结论

原来 Board1 SIL 的 29 个 unittest 场景挤在一个 CTest 条目里串行跑，合计 320 秒。现在每个场景各注册成一个 CTest，矩阵的 CTest 并行度从 2 提到 4。效果：

- fwinteg 全程从约 31.7 分钟降到 18.9 分钟（−40%）；
- 固件 CTest 在三套工具链上都快了约一半。

| 固件 CTest（fwinteg 内，`-j`） | 改前（`-j 2`） | 改后（`-j 4`） |
| --- | ---: | ---: |
| clang | 298.7 s | 157.9 s |
| gcc | 766.2 s | 357.1 s |
| sanitizer | 367.6 s | 187.5 s |

本地 `ctest -j 8`（48 项）从 275 秒降到 134–155 秒；`-j 4` 为 134 秒，`-j 6` 为 128 秒。

## 改动

- `firmware/at32f415/CMakeLists.txt`：
  - 配置时从 `tools/falconfoc-cli/test_board1_sil.py` 读出所有 `def test_*(self)`，每个方法注册一个测试，名为 `test-foc-board1-sil.<去掉 test_ 的方法名>`，命令为 `python -B test_board1_sil.py Board1SilTest.<方法>`。
  - 这个 Python 文件列入 `CMAKE_CONFIGURE_DEPENDS`，新增场景会自动注册。
  - 一个场景也找不到时，配置直接报错。
- `run_matrix.ps1`：新增 `-Jobs` 参数，默认 4（原来写死 `-j 2`）。
- `expected_tests.tsv`：`test-foc-board1-sil` 换成 29 个场景名，每套工具链 133 → 161 项，表头写明原因。
- firmware README（运行命令、按名字跑单个场景）、scripts README。

## 验证

- 本地 `ctest -j 8` 连跑两次，48 项全部通过；`-j 4`、`-j 6` 也全部通过。各场景各用自己的 SIL 进程和临时目录，并行运行没有出现串扰。
- fwinteg `test01/run1`：VERDICT PASS，0 findings。三套工具链 expected 161 / discovered 161 / passed 161。`fwinteg_verdict.py` 的结果正则能识别带点的测试名。
- 质量门禁（含 CMake 格式）通过。

## 局限

- 本机只有 4 个物理核（8 个逻辑核）。每个 SIL 场景同时占两个忙碌进程（Python 驱动与 SIL，lockstep 交替），总计约 640 核·秒的 CPU 工作量。所以 `-j` 超过 4 后墙钟时间基本不再下降，约 130 秒就是本机下限。
- 最慢的场景（转子范围与电参数辨识，单独跑 66 秒）在并行负载下要 113–262 秒，是关键路径。要再提速就得减少 lockstep 的每步往返开销，或者精简这个场景，这会改动测试内容，不在本次范围内。
- 用 `-R '^test-foc-board1-sil$'` 精确匹配旧名字已经匹配不到测试了，要改用前缀 `-R '^test-foc-board1-sil'`。
