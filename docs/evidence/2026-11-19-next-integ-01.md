## 2. 配置准入与使用方法

在 FalconFOC 源码根目录运行：

```powershell
cmake -S examples/servo -B build/servo-demo -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_BUILD_TYPE=Debug
cmake --build build/servo-demo --target falconfoc-servo-demo
$demo = './build/servo-demo/falconfoc-servo-demo.exe'
& $demo --help
& $demo --inspect --iq-limit 1.8
& $demo
& $demo --iq-limit 1.8
& $demo --faults
& $demo --recovery
ctest --test-dir build/servo-demo -R '^test-falconfoc-servo-' --output-on-failure
```

发现调用 `foc_parameter_count/at/find/get_range`。输出 ID、名称、类型、单位、当前范围、requires_reinit 及静态读回值。动态范围基于已初始化实例，初始候选的 motion Iq 则依据 Pipeline 电流上限 2.5 A。有限的命令参数允许用户在初始化前选择 Iq，运行脚本自带完整的位置、速度和 K/D 命令。

| 参数来源 | 如何生效与查询 |
| --- | --- |
| 默认虚拟 PMSM，4 极对，0.025 Wb，J=0.002 kg·m²，B=0.006 N·m·s/rad | 模型派生 Kt=0.15 N·m/A，应用指定 Frame 81。Kt 和 Frame 保持只读来源，并作为初始基底校验。 `calibration_source=HOST_MODEL`。 |
| Iq 默认 2.2 A、独立转矩 cap 0.315 N·m、K/D/FF 上界 | 通过 `foc_parameter_prepare_initial` 验证 detached candidate。候选仍没有活动实例，`foc_runtime_init` 收下同一 Pipeline 和 candidate 后，分别比较 detached 读取与 `foc_parameter_read` 读回；1.8 A 非默认配置也完成整个流程。 |
| 实时 K/D 和目标位置/速度 | 由既有 Tuning、可达性与前馈 API 构造，通过 `foc_parameter_publish_impedance` 发送完整命令，匹配当前 Session、机械 Frame 和严格递增序号。 |

命令 `--inspect --iq-limit 3` 以退出码 1 拒绝越界；非法 CLI 语法返回 2。 `--inspect` 完成一次 H0 后断言 DISABLED、INHIBIT 适配器确认及 0 UPDATE。Fault 路径单独验证 Kt=0、Frame=0、K 上限负值不提交候选，原有效配置未变。Kt 和 Frame 的只读约束由现有目录定义。Flash 与标定持久化使用既有独立流程。

## 3. 正常 IMPEDANCE 和回执见证

| 阶段 | Host 实跑事实 |
| --- | --- |
| SET_MODE → ARM → START | 先查 pending，再用相同动作、request seq、session 和 H0 时间配对 APPLIED。模式在 200 µs 确认到 IMPEDANCE，ARM 600 µs READY，START 800 µs RUNNING。START 结束时 UPDATE=0。 |
| 首个控制事务 | 新样本和命令在 1,000 µs 生效。最初 publication receipt 可读为 ACCEPTED；H0 观察到匹配 seq、源时间、H1 目标身份、健康和适配器结果后才成为 APPLIED。 |
| Plant 与观测 | 两组默认分别确认 11,996 次 UPDATE，使用被接受的 duty 驱动 23,992 个虚拟子步。位置保持、正向位移、反向速度和负载施加经过实际 Plant；每次合格 UPDATE 检查观察到的命令、Sensor 时间及 ADC 源时间。 |
| K/D、外扰与指标 | 1.45 s 发布新的完整 K/D，1.55–1.9 s 注入 0.039 N·m。反向段 RMS `ZERO_FF=0.0199641 rad`，`MODEL_FF=0.0008316 rad`，维持既有场景和比较口径。 |
| STOP | Foreground 先收到 ACCEPTED 和 pending/unconfirmed 快照，H0 在 2,400,200 µs 确认 INHIBIT、状态 DISABLED。随后水位保持 11,996，旧 Session 发布和旧 Receipt 均拒绝。 |

轮询 `foc_parameter_command_status` 观察当前状态，后续事务可覆盖此前回执。Snapshot 的 `sensor_pos_rad`、`sensor_vel_rad_s`、`sensor_us` 是 H0 已用观测；`pos_rad`、`vel_rad_s`、`Iq_plant_A` 是 Host plant 真值。 `Iq_request_audit_A` 是按 Core 与已接纳目标审计的计算请求。应用实际打印配置 Iq cap、负载、限幅、fault bitmask、action、确认及 `physical_applied=false`。无效目标或无效捕获年龄按 `invalid` 标明。 [工作流数据](2026-11-19-next-integ-01/host-workflows.txt)

Host Servo 产品集成结论不增加控制品质评级。既有 Current 短窗口、Velocity、Position/Load、Fault 等历史标签按各自研究工况保留。 [历史控制品质](2026-11-16-next-control-quality-01.md) · [Servo 前馈证据](2026-11-18-next-servo-02d.md)

## 4. 故障、拒绝和恢复

| 场景 | 实际事务断言 |
| --- | --- |
| 初始配置及命令拒绝 | 零 Kt、零 Frame、负 K 上限保留原配置和候选；运行态 NaN、Inf、越界 K/D、错误 Frame、模式错配和重复 seq 被 Control Plane 拒绝，旧合法收据与 UPDATE 水位保持。 |
| Encoder transport / 旧帧 | 虚拟传感器走正式 Encoder 错误入口；陈旧帧带原时间和 seq。H1 返回输入或次序错误，H0 走对齐/失效路径，无新 UPDATE。重复传输失效锁存 SAMPLE_INVALID，受限 CLEAR 拒绝。 |
| Output Adapter 拒绝 | 在已有非零 PI 积分时拒绝 UPDATE。测试在适配器调用边界及返回后比较实际积分，原积分快照保持、候选不提交、确认 INHIBIT，UPDATE 水位不动。 |
| Command Timeout | 停止发布合法目标继续推进。独立 COMMAND_TIMEOUT 真实锁存，最后 13 次 UPDATE 保持 13，适配器已确认 INHIBIT，旧命令和收据返回 FAULT。 |
| STOP/FAULT 同拍 | 运行中提交 STOP 并注入 `FATAL_RESET_REQUIRED`，同一个 H0 确认禁用、保留锁存，UPDATE 1→1。CLEAR 被拒绝，打印阻断原因。 |
| 合法恢复 | 同一实例，4,000 µs CLEAR accepted/pending，H0 在 4,400 µs 确认 APPLIED、DISABLED/INHIBITED。旧 Session 拒绝。新命令、新 Sensor、独立 ARM/START 后于 5,000 µs 首次恢复 UPDATE 13→14。再次 STOP，14→14。 |

异常用例均由正式应用入口驱动，程序按状态、流水线结果、计数和实际输出验证，退出码表示相关断言是否通过。 [故障原始输出](2026-11-19-next-integ-01/host-workflows.txt)

## 6. 最终问答与 INTEG-02 输入

1. **有明确入口。** 使用 `falconfoc-servo-demo` 的默认、`--inspect`、`--faults` 和 `--recovery` 命令。
2. **基础使用无需修改源码。** Quickstart 从干净目录构建；参数、运行、故障和恢复都可通过命令执行。
3. **Control Plane 实际参与。** 初始候选、参数读回、动作与 IMPEDANCE 命令和收据都经过公开 C11 API。
4. **IMPEDANCE 由正式 Runtime 执行。** H1 使用真实虚拟 Encoder 观测，H0 经 Core/Pipeline/Safety 到 Host Adapter。
5. **ARM、START、STOP 均有 H0 见证。** 前两者配对生命周期回执；STOP 核对 pending、H0 返回及确认 INHIBIT 的 Snapshot。
6. **能区分接纳、执行与拒绝。** 匹配 Session、seq、source time、H0 Snapshot 和输出确认后收据才显示 APPLIED。
7. **Virtual Motor 实际消耗已接纳输出。** 通过同一 plant 步进提供后续 ADC/Encoder，软件输出授权限于 Host。
8. **能停止及有条件恢复。** 同一实例清除合格的命令超时；Encoder Fault 和需复位的故障保持阻断。
9. **Host/Board1 边界明确。** Host C11 有 IMPEDANCE，UART V1 保留 CURRENT/VELOCITY/POSITION，Board1 ARM/START 仍锁定。
10. **继续复用原模块。** 集成放在应用和最小构建依赖，Core、Runtime、模型、协议、安全和调度归属延续。
11. **独立开发者可源码构建。** 仓库外干净目录和现有外部消费者已验收。SDK 公开发布门禁另行负责。
12. **下一阶段接入读证据。** 在既有锁定和授权约束内记录 Board/镜像/时钟身份，配对 ADC 四 Rank 原始值、RT-01 slot/token、请求和 PCCE 服务代理，记录 Encoder raw/capture/RX/close、H1 发布、H0 消费、Safety/INHIBIT 状态与 DWT 开关。将真实来源、回绕、漏帧和无效原因写入 SOFT-06 审核链，保留 V1 只读兼容及源时间/物理时间区别。INTEG-02 未启动。 [下一阶段依据](../architecture/FalconFOC_BareMetal_Execution_ADR.md)
