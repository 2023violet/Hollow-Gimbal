## 2. 复现、修复与错误结果

| 缺陷或边界 | 可复现证据 | 最小处理 |
| --- | --- | --- |
| H0 在 H1 读取快照中提交新 generation | `red-h1.log` 中嵌入真实 H0 后，实装 Board encoder completion 返回 `BUSY` 并请求停机。 | H1 在同一 admission 最多重读一次。一次冲突可发布原样本，第二次仍 `BUSY` 交给 Board 的原 INHIBIT 路径，期间不改 watermark 或伪造进度。 |
| 监督读取遇正常抢占 | `red-supervision.log` 复现单次冲突拉起 foreground heartbeat fault。 | 冲突和时间早于更新后快照的情况返回 `BUSY`、延后至下一个 due poll、无成功心跳或 watchdog 许可。真实超期继续故障，启动阶段以 boot 时间约束首次完成。独立 hook 保留旧遥测读碰撞语义，原 watchdog 回归重新通过。 |
| SPI phase 检查与 GPIO/TX 可被 H0 分隔 | 旧代码依据单次 phase 读后续动作；Host 注入过期 elapsed 和同级排队。另有事务跨越收尾、短 hold、忙总线和 sticky error 反例。 | 复用纯 C11 的 Board 时限判定。在 TMR2/TMR5 夹读后检查动作前后时间代理，超界交易丢弃。过期动作可能已写入编码器 GPIO/TX 寄存器，之后会关闭或复位并拒绝样本。没有把软件代理当作硬件引脚不越界的证明。 |

第一次 H1 重读限定为两次完整线性化校验，复制失败不提交 H1。监督在冲突前检查真实会话距上一成功发布的年龄，Board1 阈值为 1 ms。即使快照持续冲突也不能持续声称通过；内部 `foc_runtime_schedule` 仍对实际触发迟到和调用者提供的预算做判断。独立 STOP 位在快照复制和 watchdog generation 守卫中均有作用。

### SPI 事务与恢复

75 MHz PCLK2 ÷16 = 4.6875 MHz，16 bit 名义线上 3.413 µs。TMR5 在 500 µs 逻辑槽目标 +0/+20/+70 µs。TMR2/TMR5 观察下 CS ≤+10、TX [+20,+30]、Close [+70,+100]。收尾要求 RX 已服务、总线 idle、无 sticky error、RX 读后至少 2 个 1 µs 计数 tick；两次取整时钟和 APB/引脚传播仍待示波器校准。H0 可跨越任何两次寄存器访问，deadline 用动作代理和归属共同审计。 [SPI 绑定](../../firmware/at32f415/src/main.c) · [用于实装及 Host 的同一判定](../../firmware/at32f415/src/foc_board_timing.c)

| 事件 | 样本、计数与 H1 | H0 / 恢复 |
| --- | --- | --- |
| 正常帧，首帧角度有效但缺速度 | Sensor 预热；不能构造有效控制角状态，Board 按结果计连续损失。 | 禁止有效新预测。后续及时连续帧建立速度后恢复样本资格。 |
| 正常闭合且速度有效 | 传输成功且连续，`losses=0`，按最新捕获时间与 seq 发布 H1。 | H0 仅在年龄和 session 匹配时采用。 |
| CS 迟到或溢出与其它旗合并 | TIMEOUT；有未收尾帧时 OVERLAP。先关 CS，损失计数，传入无效样本。 | 请求 INHIBIT。硬件复位传输入口，下一槽重试；安全故障需正规恢复。 |
| TX 迟到、不是可发状态或 RX 错误 | 错过前置 deadline 时禁止发送；后置检查失败转错误并关闭 SPI IRQ。随后 CH2 拒绝，计损失。 | 当前源无效，INHIBIT，复位 SPI 后等下一合法槽。 |
| RX IRQ 被 H0 抢占或与 CH2 同时待决 | SPI1 可能先服务；若 close 前 hold 满足且整体窗口有效则接收。未消费 RDBF、重复、帧错误用 FRAME；没有有效已读帧、BUSY、过短 hold 或迟于 +100 用 TIMEOUT。 | 无效帧先请求 INHIBIT，再尝试全部无效的 H1 样本；积压帧不会作为新事务采纳。 |
| Close 跨界 | 前后观察任一越界的有效候选转超时。close 即使迟到仍清理和释放 CS。 | 不发布新的有效角度；采集恢复另受连续性与 Safety 约束。 |
| 连续丢帧与回归 | Board 连续损失饱和计数；重新收到帧仍需通过 2.5 ms 连续间隔和转速检查。超间隔后连续位置锁定失效。 | 不依据旧机械展开坐标工况恢复；需要重新初始化采集会话和既有控制准入。 |
| H1 status 非 OK / 持续 BUSY | 有效传输可以采得角度，但 H1 未发布，`losses` 仍表示 Encoder 连续损失，H1 状态由探针记录。 | 本拍不拿早先的 target 当成新命令；持续 BUSY、ORDER、TIMING 均保留 Board INHIBIT。首次 BUSY 通过有界验证才可成功。 |

## 4. 响应时间与 Deadline

对每个 release 分别构造响应：

```text
R = C + B_equal + B_mask + exception_overhead + sum(N_higher(R, offsets, J) * C_higher)
finish = release + R
```

`B_equal` 包含正在执行的同级 IRQ 及已排队的同级前驱，`B_mask` 包含中断屏蔽，`N_higher` 由实际释放偏移、最小间隔、抖动、sticky 事件合并和初始积压上界列出。对 H0 把 CH4 和其依赖的 PCCE 分为两个 release；对 1 级算 overflow/CH1/SPI/CH2 及同级顺序。忽略抢占且启动计数近似对齐时，在一个 1 ms 超周期内 TMR5 两个槽相对于 H0 有不同偏相。首槽近 +40/+46.4 µs 的 CH4/PCCE 可能覆盖 +70 的 close，另一槽最近对应事件偏移约 +140/+146.4。启动偏移和总线、事件延时须用板端见证修正。持续到达或极长临界区能使迭代无法在 deadline 前收敛。

| 指标 | 可检查的软件约束 | 已验证与阻断 |
| --- | --- | --- |
| `H0_RESPONSE_TIME` | 槽 +40…+110 µs 允许 CH4 请求，配对 PCCE 代理不晚于请求 +80 µs 且同槽。Runtime 以 PCCE 服务代理检查 H0 入场 delay ≤150 µs。完成余量要比较目标槽边界或 RT-02 指定 load。 | Host 验证有效交接、超期和适配器拒绝。200 µs 当前逻辑周期满足明确的 Host 成本输入；板端完整 C 与同级阻塞未定。 |
| `H1_RESPONSE_TIME` | 500 µs 周期，Runtime admission 延迟 ≤150 µs；CS/Close 决定输入时效，预算与运行中 H0 干扰另计。用 H1 发布后首次 H0 消耗校验年龄，不能以 close 已完成替代 H1 完成。 | Host 同槽夹读及发布期间抢占通过。H1 延迟到使 650 µs 角度/预测阈值失效时原样拒绝。 |

Runtime 当前 H0 200/150/100、H1 500/150/150、监督 200/150/100、遥测 10,000/500/100 µs（周期/最大迟到/输入预算），前台合计预算 150 µs。ARM 入口传入的 `cost_us=0` 是尚无本次测量的预算占位。Host 单独注入 H0 cost=101 µs 可检出预算超出。最小后续接口是保留现有前置预算，另在返回后发布 `cost_measured`、本拍实际 elapsed 和所属 token，超期标记留给本拍观测与后续安全决策。真实功率路径还需在 shadow 写入前核对当前 load 和有效期。禁止拿上一拍耗时充当本拍成本。

### 20/20 kHz 与 ADC/PWM 合同

现行 Board1 TMR1 是锁定的 200 µs 计时槽。20/20 kHz 首选的 50 µs 载波以 RT-02 的 `write < load − setup` 为硬约束。以 6.4 µs 转换、2 µs setup 为例，+40 µs 采样至下一谷只余 1.6 µs；+10 µs 至下一谷余 31.6 µs，至同峰余 6.6 µs；+18 µs 至下一谷算术余 23.6 µs。所有数仍须扣除 ADC 同步、响应、H0、提交和安全裕量；改变 load 亦改变反馈年龄和相位延迟。实际采样相位还要同时满足 RT-02 每相 CSA 窗，+10 µs 可能因低侧尚未导通而失效。10/10 kHz 同假设 +10 µs 余 81.6 µs，20/10 kHz 如仍写下一谷，每次更新的 deadline 和 20/20 相同。Host 中既有 20/20 成功、迟到、缺帧案例，且保留了 RT-02 窗口与装载反例。当前主要阻断是**有效采样窗口与物理装载事件的联合取证**，随后才能判定 CPU 和 SPI 干扰能否填入余量。 [RT-02 合同](2026-11-19-next-rt-02.md)

## 7. 交接问答

1. **H0/H1 是否存在确认的竞态** 有。H0 快照发布可把 H1 的合法读取打成 BUSY 并触发误停；前台同类问题会错误上报心跳故障。现已修复并保留持续 BUSY 的拒绝语义。inactive slot 写入本身经过嵌套测试，H0 只见完整样本。
2. **H0 主要成本** 电角预测/归约、软浮点三角和向量幅值、Current PI/SVPWM、guard/output 提交及原子快照发布。状态机和错误分支也须分类实测。
3. **H1 是否可能被 H0 抢占到错过 SPI** 可以。静态优先级和 Host 反例已证实机制，实板概率与尾部仍未知。生产关闭路径能拒绝、清理越期事务。
4. **SPI IRQ 或 DMA** 保留不阻塞的单帧 SPI IRQ。目标端没有符合公平基线的成本证据支撑 DMA。
5. **BUSY 是否导致不必要 INHIBIT** 旧行为会；新代码在 H1 最多重读一次，单次普通冲突可恢复。持续冲突仍拒绝；监督保留真实 heartbeat 超期。
6. **是否立即优化 PI/SVPWM** 不具备按路径和输入分布的硬件成本证据。先测正常、限幅、饱和和输出拒绝的完整路径。
7. **200 µs 是否满足** 软件交接和条件化 Host deadline 通过，注入迟到会被检测。AT32F415 上的所有最坏相位及 H0 完成余量仍未证明。
8. **20/20 的主要阻断** 必须先同时证明有效电流采样相位与指定装载余量，才可以用实测 CPU、ADC 同步和抢占成本裁决。
9. **插桩开销** 静态增加 Flash 1,112 B、RAM 416 B，正常嵌套栈估算增加 56 B；各路径读数和实测方案见第 3、5、6 节，目标周期负载未采集。
10. **后台长期饥饿** 有条件风险，高优先级干扰和已到达 UART 等待可能耗尽前台余量。软件每轮先做监督及有界服务，真实缺口会超时并请求停机。
11. **何种证据推翻架构** 相同算法、相位、SPI 帧、故障合同和负载下，证明 H0/H1 发布年龄、SPI close 或 shadow deadline 有可重复的不可满足上界，再公平比较更小修改与候选架构的收益和代价。
12. **能否进入 INTEG-01** 可以进入独立 Host Servo 用户入口工作。继承锁定默认、上述超期与 BUSY 语义、测试证据分类和公开合同。底层实机验证由既定后续阶段及独立授权承接，本轮结束于 RT-03。 [架构顺序](../architecture/FalconFOC_BareMetal_Execution_ADR.md)
