## 数据格式、适用身份和 API

新增可选 `falconfoc-config-store`。纯 C11 Codec 与双槽事务分别实现，生产代码通过调用方的有界读、擦除、编程接口访问设备。Host 端单独链接 `falconfoc-config-store-host`。生产层无全局可写配置、动态分配、RTOS 或 MCU 写入依赖。

[公开 C11 API](../../control_plane/include/foc_config_store.h) 支持 `validate`、`encode`、`inspect`、`decode`、`load`、`save`、`save_active`。加载与保存的报告提供活动槽、Sequence、Schema、记录大小和各槽状态。完整的 [字段矩阵和二进制布局](../control-plane/config-store.md) 定义了现有参数 ID、类型、字节序、范围和迁移规则。Schema 2 记录五项基础限额与九项保护设置，关闭 IMPEDANCE 的配置写入十项（省去四项相关限额）。诊断、命令和生命周期动作不入库。只读标定和转矩常数用于身份匹配，恢复后仍由可信配置提供。

Format 1 使用 56 B 外层头和 8 B 定长标量 TLV。当前编码长度为 136/168 B，有界解码最多 256 B、25 项。CRC 复用工程已有 IEEE 802.3 实现，覆盖头部的 Magic、Format、Schema、Sequence、长度、数量、身份与载荷。CRC 字段与最后单独写入的提交字单独处理。标准向量 `123456789 → 0xCBF43926` 及 136 B 黄金记录 `0x4F77E7E6` 通过三个工具链。编译器不直接序列化整份结构体。

记录校验 CPR、编码器方向、极对数、机械坐标身份、电角零点、编码器校准身份和 Motor setup ID。启用 IMPEDANCE 时额外检查模式适用性和可信 Kt。已知不匹配返回 `ERR_IDENTITY`，身份资料不全返回 `ERR_IDENTITY_UNKNOWN`。这些值来自已接受的 Encoder/Calibration 和应用设置，不能替代物理设备唯一身份。Codec 和存储管理器拒绝截断、重复 ID、类型冲突、过长、NaN/Inf、越界、缺失和无效组合。失败时调用方的候选维持原值。

## 双槽事务与断电证据

保存扫描两个已提交槽，选择目标槽后擦除、写入带擦除提交位的完整记录并回读。最后单独编程 4 B 提交字，再全记录回读确认。旧有效槽在整个事务中保持完整。相同时间序号且记录完全一致时选择 A；同序号不同记录和序号差恰为 `0x80000000` 返回歧义。以模 2³² 比较序号，实际保存测试覆盖 `UINT32_MAX → 0`。可从损坏或未提交槽回退到另一份完整记录。CRC 合法的未知容器格式，或最新已提交记录的未知 Schema、无效语义或身份不符，均返回失败并保留存储内容。不会因为这些语义不兼容而装载较旧的保护配置。

**HOST POWER-FAILURE MODEL PASS**。从两个不同的已提交槽开始，第三次保存打断四字节擦写/读取步骤。每种故障模型覆盖全部 110 步，并逐字段比对恢复配置的十四个静态值。

| 步骤（从 1 开始） | 断点位置 | 三种故障模型的恢复结果 |
| --- | --- | --- |
| 1–2 | 保存前扫描 | 旧记录 |
| 3–66 | 逐 4 B 擦除目标槽 | 旧记录 |
| 67–79 | 写外层头（提交字空置） | 旧记录 |
| 80–107 | 逐 4 B 写 TLV | 旧记录 |
| 108 | 回读和校验，未提交 | 旧记录 |
| 109 | 提交字编程 | 操作前、撕裂时恢复旧记录，编程成功但未确认时恢复新记录 |
| 110 | 提交后的读回与成功确认间 | 新记录 |

三种模型分别在该步骤前、部分完成和完成后丢失确认时模拟断电。**330 次中 326 次恢复旧值，4 次恢复已提交新值**。未写目标槽之外的副本逐字节比对通过。保存返回 `ERR_UNCERTAIN` 时，通过重启后重新扫描确认实际提交结果。对已提交相同候选重试，序号不增长。另验证了驱动对非对齐、越槽、超容量和 0→1 编程的拒绝，以及双损坏、格式字节翻转、有 CRC 但未来版本的分支。详细逐步数据见原始证据 ZIP。

## SOFT-02 整组恢复和版本迁移

Schema 1 是本模块独立的旧字段集，不读取、覆盖或迁移旧应用真实 Flash 数据。缺少九项保护的旧记录返回 `ERR_RECONFIRM`，只有同一身份的完整显式保护候选才能生成 `MIGRATED`。迁移保持旧记录只读，随后独立请求保存才把 Schema 2 增量提交到另一槽。旧格式里夹带保护字段、Schema 2 缺任何一项或关闭状态下仍有非法边界的记录都拒绝。SOFT-02 的运行时默认关闭策略继续适用。要把关闭状态持久化，仍需显式提供整个有效保护组。

活动实例保存以当前 Runtime 配置为基线，通过既有 Control Plane 静态配置门禁。测试覆盖合法 DISABLED 和确认 INHIBIT，以及当前 Session 不匹配、待处理 ARM、RUNNING、FAULT 的拒绝。保存不修改 Runtime 的状态和配置。加载仅生成一个候选，调用者显式初始化、经原有生命周期准入后才能运行。重新初始化前多次保存时，应按指南重送希望保留的编辑。旧 UART V1 `PARAM_SAVE` 仍返回 `NOT_SUPPORTED`。

[Host 示例](../../examples/parameters/README.md) 实际记录 A 序号 0，B 第 80 步撕裂返回 `-15`，重启恢复 A。随后 B 提交成功，重启加载序号 1。位置区间从 0.20–0.80 rad 更新为 0.30–0.70 rad，跟随从 0.10 rad / 20 ms 更新为 0.06 rad / 18 ms。每个新实例核对 14 项值，确认 INHIBIT 和零次 UPDATE。另一设备始终独立保留 A、序号 0。
