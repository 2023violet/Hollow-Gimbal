# FalconFOC License Decision Memo

对象为 Servo SDK `0.1.0-rc.1` 的 [52 文件范围](source-provenance.tsv)。本备忘录供实际权利人决定许可。原候选仍是内部快照。

**建议优先评估 Apache-2.0，适用范围限于已证实可自行授权的 FalconFOC 部分。** 面向电机控制库的商业集成，Apache-2.0 将贡献相关专利许可和终止条件写得明确。若所有者更重视简洁归属与通知、且接受 MIT 文本没有同类明确专利条款，可选择 MIT。对两者而言，当前首要工作是解决早期来源以及确认实际版权和授权主体。

## 对这 52 个文件的具体影响

- 早期 16 个文件仍为 `UNRESOLVED`。两种自有许可都要求先解决这些文件的历史权利链。若确证某个片段由 Legacy 或外部实现改编，先从实际权利人或适用上游条款确定许可基础。
- 另 36 个文件的记录支持工程上属于项目实现或集成材料。核实创作者、雇佣/职务成果、合同、共同作者、贡献输入、文档与示例的授权范围后，才能施加所选许可。Git 作者名称和现有归属线索列在矩阵里。
- 当前未识别入包第三方直引源码。若后续发现文件或片段存在独立版权，逐路径保留其条款和原声明。明确版本的 VESC 样本、Artery、CMSIS、FreeRTOS 属参考、排除或另审范围，详见[上游和 Notice 草案](upstream-and-notice-review.md)。

## 若权利人选 Apache-2.0

1. 批准实际持有人、来源与可许可路径。确认适用的贡献相关专利授权及批准主体。
2. 对该范围提供正式 Apache-2.0 文本和已确认的版权与归属。确认使用的外部例外单列。
3. 对适用的改动文件加入显著变更说明，保留相关源声明。按上游是否存在适用 NOTICE 确定传递内容，并审查项目自身的 Notice 草案。
4. 固定可复现提交与 Manifest。由所有者签署确切归档和实际允许的发布渠道。

## 若权利人选 MIT

1. 批准实际持有人、来源、年份和可许可路径。
2. 提供 MIT 原文和正确版权声明，保证所有副本及实质部分随附对应文本。
3. 保留第三方原许可及版权。逐项处理兼容性、修改与 Notices，按实际引入材料的许可执行。
4. 同样冻结精确候选并取得各发布动作的授权。

两条路径沿用同一份[所有者审批表](owner-approval-template.md)。许可选择仍待实际权利人确认。
