## 交付与数据判定

- Measurement Trace v1 采用只读 JSON Manifest + CSV，记录设备、电机、编码器和机械坐标身份、采集与参考来源、通道、单位、采集工具、实验前提、每阶段的记录数和 CSV SHA-256。Python 标准库校验文件后将相同字节交给 C11，避免校验与使用之间重复读取。 [测量需求矩阵、格式和时间域](../../calibration/MEASUREMENT_TRACE.md)
- `falconfoc-measurement-trace` 使用独立的调用方上下文，校验同一采集的身份、时间、单位、证据和完整性。输出是 SOFT-05 已有样本和回放时间。失败保持输出原值，Runner 使用分离 Workflow，不改变上次候选和现有 Runtime。 [C11 公开 API](../../calibration/include/foc_measurement_trace.h)
- `validate` 做结构、内容和样本契约预检；`replay` 调用 SOFT-05 的正式估计器，保留阶段通过、部分成功和候选准入差异；`explain` 提供拒绝原因。稳定 JSON 同时报 Trace 样本和 Workflow 实际接受的样本，保留原生质量、结果标识和审核状态。 [构建与命令](../../tools/falconfoc-calibration-replay/README.md)
- 支持四类来源声明。Host 数据标记 `PROVENANCE_DECLARED`，外部或板端声明默认 `PROVENANCE_UNVERIFIED`，仅在用户提供独立信任材料且哈希、来源及身份均匹配时标记 `PROVENANCE_VERIFIED`。自带哈希只证明内容一致，未核实外部数据只供数值诊断。工作区内没有识别到获授权且具有完整采集证据的真实包。
- 仅测得 dq 电流时，机械辨识要求先有独立 Kt 作为转矩换算依据。已知等效轴端转矩时允许 J/B 的 Kt 元数据为 0，既有 J/B 数学和质量门槛保持原样。K/D 始终要求正值、独立来源的合格 Kt。未将指令电压、目标角度、转矩指令或未知负载转换成观测。

## 时间契约与负向证据

源采样、触发、传输或转换完成分别保留。ADC 软件触发和 Encoder 片选可作为标明的代理，Host 接收时间不参与。原始时间按同钟域 UInt32 半程规则校验，回绕须声明，样本序号连续，观察到的完成时间可相等且不会倒退。缺少完成时间会增加诊断计数，Workflow 仍消费原始源时间。

ADC–Encoder 配对、Rotor 和 Offset 检查相同钟域及声明偏差，Host 标准策略允许的上限为 50 µs。LUT 和 J/B 保持原生等时要求。异步阶段各自检查，保留不同采样率，无跨时钟域转换和重采样。独立 Holdout 验收并冻结 LUT 后才解码 Rotor 和 Offset。记录 ID、原始时间和训练前缀复用检查可发现常见污染，物理独立性须从采集证据判断。

已验收重复、倒序、半程外、超龄、授权和非法回绕、完成倒退、异钟域、位置配对错位、序列缺口、捕获不完整和错误单位。故障注入也验证 ADC 通道错换、CPR 越界、错误方向、饱和、仅有电压指令、未知负载、角度参考缺失或自引用、缺 Kt、低激励、复制训练观测伪装 Holdout、取消和重启。C11 测试检查多实例和失败输出不变，旧 Runtime 与应用准入由既有 Control Plane 回归覆盖。
