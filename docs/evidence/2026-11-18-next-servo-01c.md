## IMPLEMENTED｜模型候选 API

`core/include/foc_impedance_tuning.h` 中的 `foc_impedance_tuning_design(input, candidate)` 是无状态 Core 冷路径。输入为非零模型身份、等效电机轴惯量 J（kg·m²）、明确提供的粘性阻尼 B（N·m·s/rad）或明确的 B=0 假设、目标自然角频率 ωn（rad/s）、无量纲阻尼比 ζ、已知 Kt（N·m/A）、K/D 上界、可用 q 电流上限、外环周期和额外端到端延迟预算（s）。

```text
J * acceleration + B * velocity = motor_torque - external_load_torque
ideal characteristic polynomial = J*s^2 + (B + D)*s + K
K = J * omega_n^2
D = 2 * zeta * J * omega_n - B
```

在固定目标、线性、理想转矩跟随和未饱和条件下匹配极点。Double 中间量避免合法 Float32 参数在计算中间过早失真。检查有限性、非零域、负附加阻尼、增益上界及最终 Float32 可表示性。负 D 明确拒绝。目标频率和舍入后增益对应的理想频率都须满足 `omega_n × (period + extra_delay) ≤ 0.25`。这条无量纲门槛用于初筛已申报的时序预算。理想预测和实际采样、延迟、噪声或饱和下的品质分别评估。

成功候选返回 K（N·m/rad）、D（N·m·s/rad）、按最终 Float32 增益重算的理想 ωn/ζ、模型标识、B 来源及 `Kt × Iq_limit`。输出 `valid` 代表模型设计满足已给定的静态增益上界。失败状态分别描述空指针、无效配置、数值问题、时序预算、负阻尼和增益超界，并清零输出。没有自动获知 J、B 或 Kt 的过程。MOTOR-ID 的 R/L 结果不提供这些机械参数。

调用方用实际 Runtime 的刚度与阻尼上界形成输入。候选审查通过后，显式填写 `foc_runtime_command.target.impedance` 的 K 和 D，经原 C API 和当前 Session 发布。Kt 仍来自 Runtime 初始化策略，q 上限和独立力矩上限仍归原 Runtime/Core。电流力矩预算无法保证任意误差及前馈下不饱和。整定函数不访问 Runtime，也不执行在线热更新。
