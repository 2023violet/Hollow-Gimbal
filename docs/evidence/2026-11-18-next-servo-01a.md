## Core API 和机械坐标

`core/include/foc_impedance.h` 声明三组显式值和一个入口 `foc_impedance_step(config, input, output)`。由调用方拥有输入与输出，没有控制器实例状态、动态分配、隐式时钟、外设访问或第三方依赖。成功返回 `FOC_STATUS_OK` 且结果 `valid = true`。调用方可以交错计算多组输入。

| 物理量 | API 字段 | 单位及约束 |
| --- | --- | --- |
| 连续机械位置误差 | `position_error_rad` | rad，参考减实测，保持正负方向及跨圈误差 |
| 参考和实测机械速度 | `reference_velocity_rad_s`、`measured_velocity_rad_s` | rad/s，同一轴坐标系和采样基准 |
| 刚度 | `stiffness_nm_per_rad` | N·m/rad，非负 |
| 阻尼 | `damping_nm_s_per_rad` | N·m·s/rad，非负 |
| 前馈力矩 | `torque_feedforward_nm` | N·m，有符号，和刚度及阻尼项相加 |
| 转矩常数 | `torque_constant_nm_per_a` | N·m/A，有限且严格大于零 |
| 执行器请求上限 | `torque_limit_nm`、`live_iq_limit_a` | N·m、A，有限且非负。零上限只允许零力矩 |
| 三个输出和两个标志 | `requested_torque_nm`、`limited_torque_nm`、`iq_ref_a`、`limited`、`valid` | N·m、N·m、A、布尔值、布尔值 |

本轮坐标基准是电机机械轴，正 q 电流与 Core 正机械转矩同向。调用方负责在同一坐标系形成连续位置误差，生产函数没有角度 wrap，也没有相减两个绝对 Float32 机械角。需要大行程精度时，调用方可先在同一计数域求差，或者用局部锚点形成误差，再转 Float32。本轮 Host 的坐标靠近零，以接受的整数多圈计数在 Double 中算位置和误差。齿比、效率、间隙及负载侧位置由未来关节层处理。

```text
velocity_error = reference_velocity - measured_velocity
requested_torque = Kp * position_error + Kd * velocity_error + torque_feedforward
effective_torque_limit = min(torque_limit, Kt * live_iq_limit)
limited_torque = clamp(requested_torque, ±effective_torque_limit)
iq_ref = clamp(limited_torque / Kt, ±live_iq_limit)
```

最后一次电流钳位消除 `(Kt × live_limit) / Kt` 舍入可能产生的一 ULP 越界。Core 单测用 `Kt=0.112f`、`live_iq_limit_a=1.3f` 覆盖正负方向的这一反例。接口报告 q 换算前的限幅力矩，有限精度下由最终 q 请求反算的 `Kt × Iq` 可略有舍入差。限幅标志在任一输出被缩减时置位，精确到达边界且未缩减时为假。

所有传入量及速度差、弹簧和阻尼乘积、实时力矩上限乘积、两个加法结果以及电流换算均检查有限性。空指针、非法正负域和非有限分别沿用 `FOC_STATUS_ERR_NULL`、`FOC_STATUS_ERR_INVALID_CONFIG`、`FOC_STATUS_ERR_NONFINITE`。运算溢出返回非有限错误，任何错误都将已提供的输出清零。Core 用例在生产实现前编译并运行零响应替身，第一个有效性断言以退出 1 失败。接入生产实现后，符号、三项组合、连续 16 rad 误差、限幅边界、所有输入字段 NaN/Inf、有限值溢出、交错计算和输入不变性全部通过。

## Kt 与闭环模型

Virtual Motor 使用已有通用 PMSM 轨迹，双精度 RK4。参数沿用 Rs 0.6 Ω、Ld 1.2 mH、Lq 1.5 mH、磁链 0.025 Wb、4 对极、惯量 0.002 kg·m²、粘滞阻尼 0.006 N·m·s/rad 和 12 V 母线。两臂采用相同的零初始状态、Current PI、ADC 量化、Virtual Encoder 和 Runtime 时钟，配置的 q 电流上限均为 2.2 A。Holdout 的阻抗 Kp=0.65 N·m/rad，默认 Kd=0.048 N·m·s/rad，低阻尼对照为 0.006 N·m·s/rad。请求力矩上限 0.315 N·m。参考速度、外部前馈为零，符号和前馈组合由 Core 单测覆盖。

`Kt = 1.5 × 4 × 0.025 = 0.15 N·m/A` 来自该虚拟 PMSM 的永磁转矩项。当 `Id = 0` 时磁阻转矩项为零。Host 请求 `Id = 0`，观测到最大模型 |Id| 约 0.00329 A。模型继续保留 `(Ld − Lq) × Id × Iq` 项。真实电机磁链、相序、有效 Kt、温度依赖、传动效率和轴端实测转矩尚未验证。Motor-ID 的 Rs、Ld、Lq 候选无法推导真实 Kt。

## Runtime 互操作、拒绝与权限

Host 复用 `Virtual Encoder → Sensor → H1 → Current 命令入口 → H0 → Pipeline → Current PI/SVPWM → Virtual Motor`。生产 H1 发布默认 LPF 和整数相位派生的电角；外部阻抗计算核对同一 H1 的序号、捕获时刻、有效位及原始 Encoder 的 LPF 和计数。Host 启动走已有 ARM/START，运行时同一 Session，每 500 µs 发布一次新命令。下一 H0 消费同序号、同时间戳的 q 请求。检查运行段应接受的 UPDATE 数且无拒绝，H0 的相位预测和最终输出事务仍用已有链路。

专门边界测试向组合入口提交 NaN 和陈旧样本，均拒绝且命令序号不推进。重复注入传感器帧错误由 Runtime 触发 SAMPLE_INVALID 故障锁存及 INHIBIT；STOP 进入 DISABLED 并 INHIBIT。两者均改变 Session，边界前后接受 UPDATE 计数为 3→3。Core 只产生数值目标。参考固件和生产 Runtime 没有 H1 IMPEDANCE 模式、完整 MIT Mode、实际机械阻抗辨识或真实关节输出转矩闭环。
