# FalconFOC V2 参数契约

> 状态：设计稿。除标注“已有”的条目外均未实现；已实现部分以 `protocol/README.md` 为准。
>
> 日期：2026-11-22

## 1. 目的

本文是 V2 的 PARAM_READ / PARAM_WRITE 与相关命令的契约：每个参数属于哪一组、类型和范围、什么状态下可写、写后发生什么、是否掉电保存。以后新增参数，就是在对应分组里加一行，不再逐个零散决定。

设计依据：

- 控制器不识别电机。同一台电机运行 Flash 中保存的参数；换了电机，由使用者通过上位机重新校准或写入参数。
- 参数全部可以由上位机读写。参考 ODrive、VESC，以及达妙、CyberGear 一类关节上位机。
- 电流环由电机模型和带宽推导，外环增益直接给值。这与 Legacy `applications/` 的 `foc_calib_runtime_refresh()` 以及 ODrive `motor.hpp` 的 setter 做法相同。
- 校准算法只在 MCU 上运行。上位机写入参数不属于校准。

## 2. 通用规则

| 规则 | 内容 | 状态 |
| --- | --- | --- |
| 写入状态 | 所有 PARAM_WRITE 与整组写入都要求 DISABLED，并且 INHIBIT 已确认；否则返回 BAD_STATE。运行中不改任何参数 | 已有（`foc_serial.c:584-587`） |
| 越界 | 类型不符、NaN/Inf、超出范围、违反第 2.1 节的顺序约束时，返回 INVALID_ARGUMENT，写入的值不做截断 | 已有（范围检查）；顺序约束为 P0 |
| 生效 | 写入成功后在 RAM 中生效。属于 H0 的参数，经 tuning 回执（ID 60–62）在下一个 H0 周期应用 | 已有 |
| 保存 | PARAM_SAVE 把表中“存盘 = 是”的参数写入 Flash；不保存时，重启恢复为启动值或上次保存的值 | 已有，P0 扩展字段 |
| 派生刷新 | 写入第 3.1、3.3 组，或写入电流带宽、整组写入换相组之后，执行一次统一刷新（第 7 节） | P0 |
| 下游收紧 | 写入一个上限后，依赖它的下游值如果超过新上限，会被收紧到新上限。写入的值本身从不被改动。上位机写完上限后应重新读取下游值 | P0 |

### 2.1 顺序约束

写入时检查，违反则拒绝：

- q 电流上限（ID 73）≤ 电流矢量上限（ID 68）≤ 峰值电流（ID 97，未设置时不参与）≤ 板子电流上限（2.5 A）
- 额定电流（ID 96）≤ 峰值电流（ID 97）
- 电流矢量上限（ID 68）< 过流跳闸（ID 112）≤ 电流测量量程（±3.3 A）
- 欠压（ID 114）< 过压（ID 113）≤ VBUS 测量量程（36.3 V）
- 速度参考上限（ID 72）≤ 过速（ID 115）≤ 编码器速度上限（1000 rad/s）

## 3. 参数分组

列说明：

- “写入”：单字段指 PARAM_WRITE，整组指 COMMUTATION_WRITE（第 5 节），只读指不可写。
- “状态”：已有，或分期 P0 / P1 / P2。
- 新单位编号从 11 起顺延：Ω 11，H 12，Wb 13，N·m/A 14，kg·m² 15，N·m·s/rad 16，Hz 17，V 18，rad/s² 19，ms 20，°C 21，1/s² 22。

## 4. 不是参数的量

| 量 | 处理 | 理由 |
| --- | --- | --- |
| ADC 电流零点（ID 38–40 读回） | 每次上电在 INHIBIT 下自动测一次，通过 M3-R 的噪声门限（4 counts rms）才算就绪；不存盘，不导入，不可写。CAL-1 照常重测 | 这是板子采样电路的量，随温度和板子变化。ODrive 在空闲时持续做 DC 校准且不存盘（`motor.cpp:607-619`）；moteus 每次使能都重测（`bldc_servo.cc:340-351, 1091`） |
| 编码器 CPR（ID 41） | 板级事实，只读 | 由硬件决定 |
| 板子上限：电流 2.5 A、电流量程 ±3.3 A、VBUS 量程 36.3 V、编码器速度 1000 rad/s | 编译期板级事实，作为各参数的硬上限 | `foc_board.c:78, 83-85, 140` |

## 6. 门禁

- **放行条件**：换相组有效（ID 88 = 1），并且本次上电的 ADC 零点已就绪。不检查来源，也没有手动放行开关。上位机整组写入本身就算有效来源。
- **范围**：只拦 ARM/START。校准使用 Runtime 内部路径，不受影响；SET_MODE 和参数读写不受影响。
- **顺序**：先检查 OUTPUT_LOCKED，再检查门禁，ARM 镜像的行为保持不变。
- **换相组变为无效的时机**：
  - 启动时既没有存储记录，也没有被接受的校准包，即 NOMINAL 占位值；
  - 执行 CONFIG_ERASE；
  - 启动了包含转子阶段的校准，直到转子阶段 APPLY 成功或重启。只跑电气阶段的校准不影响。
- **管不到的情况**：换了电机却没重新校准时，存储里的旧换相组仍然有效。这由使用者负责，并由保护故障层（第 3.5 节）兜底。在力矩模式下，Offset 错误产生的反向力矩不会触发任何保护规则（SIL 实测：0.5 A 指令得到 −0.48 A 的真实 q 电流）。这一局限写入用户文档。

## 7. 统一刷新

触发时机：

- 启动恢复之后；
- 校准的转子阶段 APPLY、电气阶段 TUNE 之后；
- 写入第 3.1、3.3 组任一字段，或写入 ID 104 之后；
- COMMUTATION_WRITE 之后。

派生内容：

| 派生量 | 规则 |
| --- | --- |
| Kt（ID 84） | 1.5 × 极对数 × Ψ |
| 电流 PI（ID 64–67） | R、Ld、Lq 都有效时，用 `foc_motor_pi_design()` 计算：Kp = 2π·带宽·max(Ld, Lq)，Ki = 2π·带宽·R，并做采样相位和延迟检查 |
| 电流上限（ID 68、73） | 下游收紧到 min(峰值电流, 板子上限) |
| 速度参考上限（ID 72） | 下游收紧到 min(最大转速, 1000) |
| 保护阈值 | 用于判断的额定电流、最大转速按当前档案取值 |

刷新经 H0 tuning 路径整体应用，与现有 tuning 写入的原子性相同。

## 9. 存储 format 3

内容是第 3 节中“存盘 = 是”的全部参数：

- 电机模型
- 换相组
- 用户档案
- 控制设置
- 保护阈值
- 通信
- 机械零点

另含 magic、format、长度、序号和 CRC，沿用两槽事务和提交字。具体偏移在实现时确定，约 70 个 4 字节字段，记录约 300 字节。

与 format 2 的差异：

- 不再存 ADC 零点。
- 换相组作为一个整体存储。
- 记录身份只保留板级事实（编码器 CPR、电流换算系数、相序），不再包含启动配置里的校准值（现为 `foc_board_store.c:472` 的整体比较）。换一个构建，只要板级事实相同，记录仍然可用；板级事实不同则拒绝恢复。

format 1/2 记录按兼容规则读入：可识别的字段迁移，其余取初始值。

## 12. 第一步实现设计：保护故障层

### 12.1 位置与时机

- 规则放在可移植模块 `g3/safe/foc_protect`，不访问寄存器，由 Runtime 在 H0 中调用。
- 每个 H0 周期在 pipeline 步进之后评估，前提是本周期开始时处于 RUNNING 且步进成功。
- 电气规则使用本周期解码的相电流和 VBUS；运动规则使用 H1 发布的机械速度、外环速度参考和 q 电流参考。
- 触发时调用 `foc_pipeline_request_inhibit()`，锁存故障并 INHIBIT。软件保护最多晚一个 H0 周期（200 µs）；更快的硬件级过流由 DRV8311 自带的 OCP 负责。
- 只有本周期新出现的保护故障会被锁存。

### 12.2 故障位

接在 `foc_safe.h` 现有的 bit 0–8 之后：

| 位 | 名称 |
| --- | --- |
| 9 | OVER_CURRENT |
| 10 | OVER_VOLTAGE |
| 11 | UNDER_VOLTAGE |
| 12 | OVER_SPEED |
| 13 | SUSTAINED_CURRENT |
| 14 | STALL |
| 15 | TRACKING_DIVERGENCE |

### 12.3 规则

| 规则 | 条件 | 适用模式 |
| --- | --- | --- |
| 过流 | 三相电流绝对值的最大值 > ID 112 | 全部（含 CALIBRATION） |
| 过压 / 欠压 | VBUS > ID 113 或 < ID 114，连续 3 个 H0 样本 | 全部（含 CALIBRATION） |
| 过速 | 机械速度绝对值 > 过速阈值（ID 115；为 0 时取 1.25 × ID 72） | CURRENT、VELOCITY、POSITION |
| 持续大电流 | 实测 d/q 电流矢量幅值 ≥ 0.95 × ID 68，持续 ID 116 | CURRENT、VELOCITY、POSITION |
| 堵转 | 实测电流幅值 ≥ 0.95 × ID 73，且机械速度绝对值 < 0.05 × ID 72，持续 ID 117 | VELOCITY、POSITION |
| 跟踪发散 | 按 ID 118 分窗统计：窗口内 q 电流参考绝对值 ≥ 0.95 × ID 73 的样本过半，且该窗口的平均速度误差没有比上一个这样的窗口降低至少 2%，即跳闸。饱和样本不过半的窗口清除比较基准；没有外环参考时规则复位 | VELOCITY、POSITION |

- CALIBRATION 模式是电压开环，只检查电气规则；这和 Legacy 对电压模式豁免堵转判断的做法相同。
- 第一步还没有用户档案，额定电流、最大转速暂用 ID 68、ID 72 代替；第二步改用 ID 96、ID 98。
- 正常的加速和反向过程中，平均误差逐窗口下降，不会触发跟踪发散。
- 最初的设计要求"速度与参考符号相反"并在单个窗口内连续成立。SIL 实测发现，极对数不匹配时转子会在 -5 到 +4 rad/s 之间来回摆动，电流只有约 56–62% 的时间饱和，每个窗口都会被打断，规则始终不触发。因此改为上面的分窗统计。

### 12.4 初始值依据

| ID | 初始值 | 依据 |
| --- | --- | --- |
| 112 | 3.0 A | 介于 2.5 A 控制上限和 ±3.3 A 电流测量量程（0.5 V/A，3.3 V ADC）之间；上限 3.2 A |
| 113 | 22 V | 原理图标注 VM 输入 5.25–20 V；DRV8311 VM 绝对最大 24 V（数据手册 7.1 节），所以上限取 24 V |
| 114 | 5.0 V | 略低于板子输入下限 5.25 V；下限 3.0 V 是 DRV8311 推荐工作电压的最小值（UVLO 约 2.7 V） |
| 115 | 0（自动） | 随 ID 72 变化，避免改速度上限时违反顺序约束 |
| 116 | 1000 ms | 允许加速时短时打满电流 |
| 117 | 200 ms | 与 Legacy 的 `FOC_STALL_TRIP_MS` 相同 |
| 118 | 300 ms | 允许阶跃和反向时的短暂饱和 |

这些值都需要在实物板上确认。

### 12.5 参数与存储

- ID 112–118 走 tuning 通道：在 H0 应用，回执见 ID 60–62，只能在 DISABLED 时写；顺序约束由 Runtime 检查。
- 第一步只在 RAM 中生效。format 2 记录里没有这些字段，启动恢复时保留它们的启动值；第二步引入 format 3 后再存盘。

### 12.6 锁存快照与清除

- 第一次保护跳闸时，H0 锁存以下内容：H0 时间、故障位、模式、机械速度、速度参考、实测 id/iq、q 电流参考、VBUS、相电流峰值。
- 新消息 0x22 FAULT_SNAPSHOT_READ 读取快照，响应 39 字节（布局见 protocol README）。
- FAULT_CLEAR 原来只接受单独的 COMMAND_TIMEOUT，现在扩展为：锁存的故障只包含 COMMAND_TIMEOUT 和保护类故障时可以清除。条件和原来一样（INHIBIT 已确认、指令已撤回、采样新鲜）；如果锁存了电压类故障，还要求新鲜样本的 VBUS 已回到 ID 114–113 之间。清除生效时快照一并清空。其余故障仍需重启。

### 12.7 SIL 验证

- **场景等价性**：用 NOMINAL 配置（7 对极、Offset 0）去驱动 Offset 或极对数不同的 SIL 电机，和"换电机后沿用旧档案"在物理上是同一种换相错误，因此可以不跑校准，直接覆盖第 3 节的换电机矩阵。

## 13. 第二步实现设计：电机档案、统一刷新、format 3

### 13.1 范围

本步实现：

- 电机模型 ID 80–86（Kt 只读，J/B 只存不用）
- 用户档案 ID 96–99（减速比只存不用）
- 电流环带宽 ID 104
- 统一刷新
- CAL-3/4/5 写入档案
- 存储 format 3：存档案和保护阈值 ID 112–118

留到后续步骤：

- 换相组整组写入、门禁、每次上电测 ADC 零点、CONFIG_ERASE 清 RAM：第三步（上位机换电机流程）。
- 位置 Ki（ID 105）、加减速（ID 106/107）、机械零点（ID 124）：按各自分期。

### 13.2 档案放在哪里

档案并入 Runtime 的 tuning 候选（`struct foc_runtime_tuning.profile`），和 PI、限值、保护阈值一起由 H0 整体生效。这样只有一个事实来源，不会出现"档案已改、Runtime 没生效"的分叉。

Runtime 只校验档案自身的范围和顺序约束，并用额定电流、最大转速推导保护基准：

- 电流矢量上限（ID 68）≤ 峰值电流（ID 97）；
- 速度参考上限（ID 72）≤ 最大转速（ID 98）；
- 额定电流 ≤ 峰值电流。

从模型设计 PI 由板级的 `foc_board_profile` 完成，复用 `foc_motor_pi_design()`。

### 13.3 统一刷新

| 触发 | 动作 |
| --- | --- |
| 写 ID 80–82 或 104 | R、Ld、Lq 都有效时重算电流 PI（ID 64–67）；设计不通过（R·T/L、采样相位、延迟相位超限）就拒绝这次写入 |
| 写 ID 97 | 把 ID 68、73 收紧到峰值电流以内 |
| 写 ID 98 | 把 ID 72 收紧到最大转速以内 |
| 写 ID 96、98 | 保护基准随之改变：持续大电流基准取额定电流（未设置时取 0.95 × ID 68），堵转转速基准取 5% 最大转速（未设置时取 ID 72） |
| CAL-3/4/5 的 TUNE | 写入实测的 R/Ld/Lq/Ψ，用 ID 104 的带宽重算 PI，替代写死的 150 Hz |

- 刷新得到的是一个完整的 tuning 候选，经 H0 一次性生效；候选被拒绝时，参数不变。
- **启动恢复不重新推导**，直接应用存下来的 PI。这样用户手动调过并保存的 ID 64–67 不会在重启后被模型值覆盖。这一点和第 7 节原来的写法不同。

### 13.4 带宽上限

H0 周期为 200 µs，PI 设计要求采样相位 2π·f·T ≤ 0.3，因此 f ≤ 238 Hz；延迟相位的限制更宽。ID 104 的写入范围定为 10–235 Hz。

设计时采样周期和更新延迟都取一个 H0 周期（延迟按上限算，比 CAL-5 原来用的 160 µs 保守）；在 235 Hz 以内，得到的增益与原来相同，只有质量检查的余量略小。

### 13.5 format 3 记录

| 字节 | 内容 |
| --- | --- |
| 0–135 | 与 format 2 相同（含 ADC 零点与转子校准） |
| 136–179 | 档案：R、Ld、Lq、Ψ、J、B、额定电流、峰值电流、最大转速、减速比、带宽（11 × f32） |
| 180–207 | 保护阈值：ID 112–115（4 × f32）、ID 116–118（3 × u32） |
| 208 | CRC-32（字节 4–207），记录共 212 字节 |

- 读入 format 1/2 记录时，档案和保护阈值取启动值。
- 这一步暂不改变：
  - ADC 零点继续存盘，要等第三步实现每次上电测量后才能去掉；
  - 记录身份的比对方式。

  这两项与第 9 节原来的写法不同。

### 13.6 实现补充

- 统一刷新只对档案字段执行。写 ID 68、72 时不做收紧，超出峰值电流或最大转速就由 H0 拒绝，不会悄悄截断。
- 任何生效的 tuning 只要把 ID 73 降到远程电流指令上限（ID 2）以下，ID 2 都会随之降低，否则存盘检查（ID 2 ≤ ID 73）无法通过。
- SIL 结果：`profile` 场景在 lockstep 和 free-run 下都通过，SIL 单元测试共 13 项全部通过。

## 14. 第三步实现设计：门禁、换相组写入、每次上电测零点、擦除复位

### 14.1 换相组来源与有效性

| 来源 | 值 | 换相组是否有效 |
| --- | --- | --- |
| 启动占位（NOMINAL） | 0 BOOT | 否 |
| 本次校准 | 1 RUN | 是 |
| 存储恢复 | 2 STORAGE | 是 |
| 上位机整组写入 | 3 HOST | 是 |
| 编译进固件的校准包 | 4 SUPPLY | 是 |

只读参数 ID 88 = 换相组是否有效，ID 89 = 来源，ID 90 = ADC 零点状态（0 等待测量，1 就绪，2 上次测量被拒绝，稍后重试）。

### 14.2 COMMUTATION_WRITE（0x53）

- 载荷 7 字节：极对数 u16（1–64）、编码器运行方向 i8（±1）、电角 Offset f32（[0, 2π)）。
- 要求 DISABLED、INHIBIT 已确认，且没有校准在运行。
- 沿用当前生效的 ADC 零点组成快照，和校准 APPLY 一样在 quiesce 下重新初始化，然后重新应用 tuning。成功返回 APPLIED，来源变为 HOST。
- ID 17 可写：换相组有效时只改 Offset，走同一路径；换相组无效时返回 BAD_STATE。

### 14.3 每次上电测 ADC 零点

- 换相组有效且零点未就绪时，校准管理器自动启动一次只测零点的运行（阶段掩码 4，CALIBRATE_START 也接受）：在 INHIBIT 下采 256 帧，噪声不超过 4 counts rms，然后用新零点替换当前快照的零点并重新初始化。整个过程不驱动电机。
- 失败后每 1 s 重试一次。
- 一次包含转子阶段的校准，在 APPLY 时同样把零点置为就绪。
- 存储里的零点只在新测量完成之前生效。门禁要求本次上电测到的零点，所以 format 3 的零点字段保留但不再决定能否运行，不需要升级到 format 4。

### 14.4 门禁

ARM/START 在 OUTPUT_LOCKED 检查之后依次判断：

- 换相组无效：返回 NOT_CALIBRATED（结果码 15）。
- 零点未就绪或校准正在运行：返回 BUSY，上位机重试即可。

### 14.5 CONFIG_ERASE

擦除 Flash 成功后，在 quiesce 下把 Runtime 恢复为启动配置：NOMINAL 或 SUPPLY 快照、启动时的 tuning、RAM 策略的默认值。来源回到 BOOT（或 SUPPLY），零点重新等待测量。

### 14.6 SIL 测试方式

原来从 NOMINAL 直接运行的场景，改为先经串口用 COMMUTATION_WRITE 写入启动时的换相组（7 对极、方向 −1、Offset 0），等零点就绪后再运行。这就是上位机导入离线校准的真实流程，SIL 里不加测试专用的绕过开关。

### 14.7 实现补充

- **自动测零的时机**：COMMUTATION_WRITE 或擦除复位后，先等 100 ms，让编码器速度估计稳定，再开始测零。只有"零点噪声过大"这种测量本身被拒绝的情况才按 1 s 间隔重试；"转子在动""tuning 待生效"这类暂时情况在下一次轮询就重试，不计入重试间隔。
- **传感器预热期（Runtime）**：任何一次重新初始化之后，到 H1 第一次发布传感器之前，处于 DISABLED 的 H0 只保持 INHIBIT 和心跳，不把没有角度的采样计入无效采样锁存，返回值仍是 ALIGNMENT。不这样做的话，写入换相组或擦除复位后约 1 ms 内就会锁存 SAMPLE_INVALID；上电时没出现这个问题，只是启动顺序碰巧让编码器先出数。
- **上位机流程**：`falconfoc_cli.py motor-setup`，依次执行校准、写入额定电流/峰值电流/最大转速/带宽、保存。
- **SIL `swap` 场景**：在 lockstep 和 free-run 下都通过。
- **已知局限（后续已修复，见第 15 节）**：CAL-3 的 R/L 拟合对 0.35 Ω、0.7/1.0 mH 这类低电阻、低电感电机会失败。
- **极对数范围**：CAL-2 只识别 1–30 对极，COMMUTATION_WRITE 接受 1–64 对极；31–64 对极只能通过导入写入。
- **资源**：默认镜像 text 81,000 B（+1,824 B），bss 12,584 B（+208 B，用于擦除复位的启动 tuning 和快照副本）。

## 15. 校准适用范围修复（CAL-3/CAL-4）

- **CAL-3 根因**：`foc_motor_id` 在配置阶段要求"最大采样间隔 × 最大电阻边界 ≤ 0.3 × 最小电感边界"，迫使 Board1 把电感下限设为 0.8 mH、电阻上限设为 1.15 Ω。凡是 L < 0.8 mH 或 Rs > 1.15 Ω 的电机都报 RANGE，不管它的极点实际上能不能分辨。
- **CAL-3 修复**：这条约束改为对拟合出的那一组值检查（间隔 × Rs / L ≤ 0.3，否则 RANGE），配置边界放宽为 Rs 0.03–10 Ω、L 0.05–50 mH。
- **CAL-4 根因**：q 轴电压档位固定为电压上限的 ±15%/±30%。低电阻电机在反向切档时，电流约为 3a/Rs，超过电流上限，电压驱动随之停止输出，报 DRIVE 失败。
- **CAL-4 修复**：基础档位 a = min(0.15 × 电压上限, 0.2 × 电流上限 × CAL-3 测得的 Rs)。
- **SIL 结果**：0.1 Ω/0.3 mH、0.2 Ω/1.3 mH、0.35 Ω/0.4 mH、0.35 Ω/1.0 mH、0.45 Ω/1.3 mH、1.3 Ω/1.3 mH、2.0 Ω/2.0 mH、Ψ = 0.02 Wb 都能完成校准，Rs 和 Ψ 准确。calibrate-faults 场景的失败用例改为一台极点确实分辨不了的电机（1.3 Ω/0.5 mH，Rs/L = 2600 /s）。
- **仍存在的精度现象**：Ψ = 0.02 Wb 的高磁链电机，Lq 测成 1.05 mH，实际 1.3 mH，偏低约 19%，推测是 q 轴激励时转子转动带来的反电动势干扰。它仍在 d/q 一致性容差内，PI 取 max(Ld, Lq)，结果偏保守。
- **极对数范围**：按默认处理，CAL-2 维持 1–30 对极；COMMUTATION_WRITE 接受 1–64 对极，31–64 对极只能通过导入写入。

## 16. P1 第 A 步：输出端坐标系（减速比、机械零点、SET_ZERO）

### 16.1 换算位置

只在串口边界（`foc_serial`）换算，Runtime、保护、轨迹、FAULT_SNAPSHOT_READ 仍用电机侧：

- 输出位置 = 电机位置 / 减速比 − 零点偏移；输出速度 = 电机速度 / 减速比。
- 输出侧：SETPOINT 的速度和位置目标、TELEMETRY 字节 38/42、远程位置上限 ID 3。
- 电机侧：速度上限 ID 72、最大转速 ID 98、过速 ID 115。速度目标乘以减速比后不得超过 ID 72，否则 INVALID_ARGUMENT。
- TELEMETRY 追加字节 75/79：电机侧位置和速度，长度 75 → 83。

### 16.2 零点

- ID 124 归串口层，与 ID 2、3 同类：写入立即生效（APPLIED），不经 H0。
- SET_ZERO（0x54，空载荷）：零点 = 当前电机位置 / 减速比，返回 APPLIED 和零点值；需要 DISABLED 且 INHIBIT 已确认，传感器新鲜，校准运行中返回 BUSY。保存仍需 PARAM_SAVE。
- ID 99、124 和 SET_ZERO 都只在 DISABLED 下接受（参数写入本来就有这一条），保证已保持的目标不会跳变。
- CONFIG_ERASE 把 ID 124 恢复为 0（ID 99 随启动 tuning 恢复为 1）。

### 16.3 存储 format 4

216 字节：format 3 的 0–207 不变，208 为零点偏移 f32，CRC 移到 212。format 3 记录照常读入，零点取 0。

### 16.4 掉电保持的边界

Board1 编码器是单圈绝对式，上电时电机位置从单圈角度 [0, 2π) 开始；校准、COMMUTATION_WRITE、CONFIG_ERASE 的重新初始化也会让电机位置回到单圈角度。所以掉电后同一输出位置只在一个电机圈（输出侧 2π/减速比）内一致；跨圈需要上位机重新回零。

### 16.5 结果

- SIL `frame` 场景在 lockstep 和 free-run 下通过：减速比 3 时输出位置 1.0 rad 对应电机 2.99 rad，输出速度 2 rad/s 对应电机 5.98 rad/s；运行中 SET_ZERO 和 ID 124 写入被拒；SET_ZERO 后位置为 0，再走 0.5 rad 正确；保存后掉电恢复零点和减速比；擦除后恢复为启动值。
- 资源：默认镜像 text 81,544 B（+544 B），bss 12,592 B（+8 B）。

## 17. P1 第 B 步：加减速与轨迹规划

### 17.1 位置 Ki 的结论

位置 P + 速度 PI 的串级结构下，恒定负载时速度积分器要停止变化，速度误差必须为 0，即 Kp_pos × 位置误差 = 0，所以位置误差会自己归零。SIL 实测（`--load-torque-nm`，默认增益，保持 1.0 rad）：

| 负载 | 速度 Ki | 稳态误差 |
| --- | --- | --- |
| 0 | 1.4 | 0.00004 rad |
| +0.04 N·m | 1.4 | 0.00004 rad |
| −0.04 N·m | 1.4 | 0.00004 rad |
| +0.04 N·m | 0 | 0.53 rad |

0.00004 rad 小于编码器一个计数（96 µrad）。位置 Ki 与速度 Ki 作用重复，ID 105 删除。

### 17.2 规划器

- `foc_trajectory` 增加减速度：速度同向增大用加速度，减小或反向用减速度；`max_decel_rad_s2` 为 0 时沿用加速度，原有调用不变。
- 新增 `foc_trajectory_track_step`：会话开始时用实测位置播种，之后只按目标积分计划位置和计划速度，不再读实测位置；刹车速度用离散公式 v·dt + v²/(2·减速度) = 剩余距离，避免越过目标；速度能在一步内减到 0 时到位。
- Runtime 位置模式（轨迹启用时）：速度参考 = 计划速度 + Kp_pos × (计划位置 − 实测位置)，再限幅到 ID 72。原来基于实测位置的 `foc_trajectory_position_step` 保留给已有调用，Runtime 不再使用。
- 原规划器进入容差后速度参考恒为 0 的死区随之消失。

### 17.3 参数

- ID 106/107 进入 Runtime tuning，电机侧单位，与 ID 72、98、115 一致。0 表示不限（内部取 1e6 rad/s²）。任一非 0 即按 ID 72 的速度上限启用规划；两者都为 0 时关闭。
- (0, 0.1) 之间的值由 H0 拒绝，返回 INVALID_ARGUMENT。
- 存储升为 format 5（224 字节）：212/216 为加速度/减速度，CRC 在 220；format 4 读入时两者为 0。

### 17.4 结果（SIL `trajectory`，lockstep 与 free-run 通过）

场景中速度环增益按 SIL 电机的 J 写成 Kp 1.14、Ki 17（约 60 rad/s，第 C 步将由 J 自动推导）。Board1 默认 0.18/1.4 只有约 9.5 rad/s，跟不上 40 rad/s² 的减速。

- 速度 0→10 rad/s（加速度 20）：到 5 rad/s 用 0.25 s（规划 0.25 s）；不限时 0.045 s。
- 速度 10→0（减速度 40）：降到 5 rad/s 用 0.131 s（规划 0.125 s），降到 1 rad/s 用 0.229 s（规划 0.225 s）。
- 位置 6 rad 梯形（加速 20、减速 40、巡航 12 rad/s）：0.906 s 到达 0.01 rad 以内（规划 0.95 s），峰值速度 12.23 rad/s，过冲 0.026 rad，2 s 时误差 0.0005 rad。
- 恒定 0.04 N·m 负载下保持：iq 0.38 A，稳态误差 0.0003 rad。
- 越界值被拒，保存后掉电恢复，擦除后回到 0。

### 17.5 已知局限

- 过冲 0.026 rad 来自没有加速度前馈：计划加速度所需的力矩只能由速度误差产生。第 C 步有了 J 之后加入 J·a/Kt 前馈。
- 加减速能力受电机力矩限制，设置值超过电机能力时实际会跟不上，规划器不检查。
- 资源：默认镜像 text 82,524 B（+980 B），bss 12,648 B（+56 B）。

## 18. P1 第 C 步：惯量辨识（CAL-7）、由 J 推导增益、前馈

### 18.1 CAL-7

- 阶段掩码 8，单独或与 1–3 组合（9–11）；不进默认流程，因为轴要带着负载转动。没有电气阶段时需要档案里已有 Rs、Ld、Lq、Ψ。
- 激励：转子角上的 q 轴电压，幅值同 CAL-4（反向时不超过 60% 电流上限）。转子越过起点 ± ID 109 的一半，或速度超过 ID 72 的 80%，就反向；反向时反电动势帮助制动，所以停下的位置不超过 ID 109。
- 窗口自适应：先探测 3 次换向，窗口取换向间隔的 1/10（5–500 个 H0 周期），再采集至少 4 次换向和 40 个窗口（最多 12 s）。固定窗口在小惯量上抹平换向瞬态（+22%），在大惯量上速度变化淹没在噪声里使 J 偏小（−33%）。
- `foc_mechanical_id` 的预检查 `B_max·间隔/J_min ≤ 0.3` 与 CAL-3 的问题相同，改为拟合后检查 `B·间隔/J ≤ 0.3`。
- 失败码 17 INERTIA（细节为估计器的 `foc_calibration_failure`），状态 16 INERTIA；CALIBRATE_READ 字节 71 第 3 位、字节 72 第 4 位。

### 18.2 由 J 推导增益（ID 108）

- ω = 2π × ID 108（默认 10 Hz），Kt = 1.5 × 极对数 × Ψ：速度 Kp = J·ω/Kt，Ki = Kp·ω/4，位置 Kp = ω/4。
- 触发：写 ID 83、85、104、108，或 CAL-7 的 TUNE。带宽超过 ID 104 的 1/5 或 100 Hz（H1 2 kHz 的 1/20）时拒绝。J 未设置时保留手动增益。
- ID 69/70 的写入范围放宽到 0–1000 / 0–100000，容纳大惯量推导出的增益。

### 18.3 前馈

轨迹规划启用且 J、Ψ 已设置时，H1 在速度 PI 输出上加 (J·计划加速度 + B·计划速度)/Kt，限幅到 ID 73。规划器输出计划加速度。

### 18.4 结果（SIL）

| 转子 J / B | 掩码 | J 误差 | B 误差 |
| --- | --- | --- | --- |
| 2e-5 / 5e-5 | 8 | +0.6% | +3.9% |
| 5e-5 / 2e-4 | 8 | +1.3% | +1.0% |
| 0.002 / 0.006 | 10（电气 + CAL-7） | +1.8% | −0.8% |
| 0.01 / 0.02，行程 1 rad | 8 | +1.0% | −1.5% |

- 行程：1 rad 时最大偏离 0.65 rad；π 时最大偏离 2.3 rad。
- 6 rad 梯形移动（加速 20、减速 40）：手写增益无前馈时过冲 0.026 rad；CAL-7 后推导增益 + 前馈，过冲 0.00007 rad，2 s 误差 0.00004 rad。
- 保存后掉电恢复 J、B 和推导增益。SIL `inertia` 场景在 lockstep（约 19 s）和 free-run 下通过。

### 18.5 已知局限

- J = 5e-5 的小惯量电机在 CAL-3 失败：q 轴 R/L 脉冲会推动转子。这是 CAL-3 已有的问题，CAL-7 单独运行（掩码 8）不受影响。（已修复，见第 19 节。）
- 极重或阻尼极大的负载（SIL：J 0.05、B 0.05）在 20% 电流下 10 s 内凑不满 3 次换向，返回 TIMEOUT。
- 辨识出的 J 包含所连负载；负载变化后需重新运行 CAL-7。
- 存储升为 format 6（232 字节）：220/224 为 ID 108/109，CRC 在 228；format 3–5 恢复时 ID 108/109 沿用启动值。
- 资源：默认镜像 text 88,024 B（+5,500 B，主要是 `foc_mechanical_id` 的双精度软件运算），bss 13,112 B（+464 B）。

## 19. CAL-3 小惯量修复

### 19.1 根因

- q 轴 R/L 脉冲产生转矩，空载转子在一级脉冲内加速到 Kt·i·T/J，反电动势 ke·ω 进入电压方程，而拟合模型只有 R·i + L·di/dt。
- 反电动势与测试信号之比约为 ke·Kt·T/(J·R)，与脉冲幅值无关：降幅值只会让静止检查通过，偏差不变。
- SIL（0.6 Ω、1.5 mH、Ψ 0.01）：J 2e-3 时 Lq −1.4%，3e-4 时 −10.3%；J ≤ 2e-4 时转速超过 1 rad/s 的静止门限，报 RL / PRECONDITION。

### 19.2 修复

- `foc_motor_id` 增加 q 轴选项 `fit_back_emf`：每个端点带转子机械角，窗口内反电动势积分 = ke·(角度终点 − 角度起点)，作为第三列回归量，不对速度求导。允许转动；窗口平均速度超过 ID 72 报 PRECONDITION；速度 RMS 低于 0.05 rad/s 时发布原两项拟合（逐位相同）。
- 转动时 R 取 d 轴结果（`known_rs_ohm`，`rs_fixed`），q 轴只拟合 L 和 ke。小惯量下一级脉冲内电流形状由机械决定，i 与 di/dt 成比例，自由 R 与 L 分不开（SIL：J 3e-6–5e-6 时三列激励 0.002–0.018，低于 0.02）；固定 R 后各 J 下 Lq 误差都在 0.4% 内。
- 时间对齐：编码器按 H1（2 kHz）采样，H0 记录里的角度比电流旧 0–500 µs。旧角度会在 R 上加 ke·Kt·延迟/J（SIL 实测约 370 µs，J 2e-5 时 q 轴 Rs +23%）。H0 记录增加 ADC 孔径时刻（`runtime->adc.produced_us`）与编码器采样时刻；CAL-3 记录等到孔径之后的编码器样本到达，再把角度线性插值到孔径。
- 不新增参数和协议字段；入口仍是 CALIBRATE_START 与 `motor-setup`。`back_emf_v_s_per_rad`（极对数 × Ψ）只在估计器结果里，作诊断。

### 19.3 结果（SIL `light-rotor` 场景，CAL-3/4/5；第 20 节改名为 `rotor-range`）

### 19.4 已知局限

- 插值假设两次编码器采样之间加速度近似恒定；SIL 中 1e-6 的转子仍在误差 0.4% 内，实板编码器量化与噪声的影响要上台架验证。

## 20. CAL-4 重转子修复

### 20.1 根因

- CAL-4 依次跑 +a、+2a、−a、−2a 四档，原来每档固定等 400 ms 再采 4 个窗口，每个方向需要 8 个窗口。
- 电压模式下转速时间常数 τ ≈ J·Rs/(ke·Kt)（再加阻尼）：J 0.002 约 0.16 s，J 0.02 约 1.6 s。J 0.02 时 +2a 档结束只到 2.47 rad/s（稳速约 5.7），−a 档整档仍在正转，到 −2a 档才过零，负方向窗口不足，报 FLUX（SAMPLE_COUNT）。

### 20.2 修复

- 每档至少 400 ms（不变），之后每 100 ms 检查一次：转速取这 100 ms 内的平均值（编码器角度差 / 编码器采样时间差，没有滤波滞后，也不会在低速时出现台阶）。
- 稳定判据：转速方向与档位一致，电气转速至少 2 rad/s（估计器单窗下限 1 rad/s 的两倍），且距稳态不超过 5%。距稳态由连续两次变化 d1、d2 估计：指数逼近时剩余 = d2·r/(1−r)，r = d2/d1，与 τ 无关；单次变化不超过转速的 0.3% 也算稳定。
- 每档最多等 10 s，超时报 TIMEOUT（12）。估计器、协议与参数不变。

### 20.3 结果（SIL `rotor-range` 场景，CAL-3/4/5）

| --- | --- | --- | --- |
| 2e-5 | 1.7 s（不变） | DONE | +0.00% |
| 2e-3 | 1.9 s（+0.2 s） | DONE | +0.04% |
| 0.02 | 12.3 s | DONE | +0.01% |
| 0.05 | 23.2 s | DONE | −0.00% |
| 0.1 | 24.4 s 后 | TIMEOUT | — |
| 0.2 | — | TIMEOUT | — |

- `light-rotor` 场景改名 `rotor-range`，增加 J 0.02、0.05 与 0.2（期望 TIMEOUT）；各完成用例 Rs、Ld、Lq、Ψ 误差均在 0.5% 内。

### 20.4 已知局限

- 能完成的最大惯量取决于 τ：SIL 电机（Kt 0.105 N·m/A、0.6 Ω）约 0.05 kg·m²。更重的负载需要在 CAL-4 前卸载，或把电机参数手填。
- 实板速度来自 14 位编码器，100 ms 平均的分辨率约 0.004 rad/s；噪声对稳定判据的影响要上台架验证。
- 资源：默认镜像 text 90,744 B（+400 B），bss 14,368 B（+32 B）。

## 21. 驱动器故障锁存（NFAULT，故障位 16）

- DRV8311H（硬件版本）在过流（5 A，MODE 47 kΩ）、VIN_AVDD/AVDD/电荷泵欠压和过温关断时把桥臂置高阻、拉低 nFAULT，5 ms 后自动重试；nSLEEP 硬接上拉，固件无法关断驱动器，所以由 MCU 锁存，防止持续短路时每 5 ms 冲击一次。VM 欠压不报告到 nFAULT，过温预警默认不报告。
- 板级 H0 每周期读一次 PB2（`foc_board_adc.driver_fault_line`，ARM 读 GPIO，SIL 用虚拟线），连续 2 次为低时 Runtime 输入 `driver_fault` 为真；H0 在本周期请求 INHIBIT 并锁存 DRIVER_FAULT（任何状态）。已锁存后不再重复请求，H0 照常运行，心跳不受影响。
- FAULT_CLEAR：DRIVER_FAULT 加入可清除集合，条件同其他保护故障，另需 nFAULT 已释放；仍为低时清除被拒绝（clear_result REJECTED）。
- SIL `driver-fault` 场景：运行中 nFAULT 拉低 → 只锁存 DRIVER_FAULT；仍为低时清除被拒绝；释放后清除生效并可重新运行；100 µs 毛刺（最多 1 次采样）不锁存。
- 局限：走停机请求通路，不产生 FAULT_SNAPSHOT_READ 快照；实板 nFAULT 波形与毛刺需上台架确认。资源：默认镜像 text 91,028 B（+148 B），bss 14,376 B（+8 B）。
