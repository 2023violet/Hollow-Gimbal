## 实际运行命令

准备 CMake 3.25+、Ninja 与 C11 编译器。从包含本轮示例的源码根目录执行三个步骤。

```powershell
cmake -S examples/servo -B build/servo-demo -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_BUILD_TYPE=Debug
cmake --build build/servo-demo --target falconfoc-servo-demo
& ./build/servo-demo/falconfoc-servo-demo.exe
```

```powershell
& ./build/servo-demo/falconfoc-servo-demo.exe --faults
ctest --test-dir build/servo-demo -R '^test-falconfoc-servo-' --output-on-failure
```

将示例的三个文件复制到独立目录后，指定真实 SDK 源码根目录。下列命令中的三个路径由调用方选择，可以包含空格。GCC 用独立的构建目录配置。

```powershell
cmake -S "$demoSource" -B "$demoBuild" -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_BUILD_TYPE=Debug "-DFALCONFOC_SOURCE_DIR=$falconSource"
cmake --build "$demoBuild" --target falconfoc-servo-demo
& "$demoBuild/falconfoc-servo-demo.exe"
& "$demoBuild/falconfoc-servo-demo.exe" --faults
```

## API、时钟与输出事务

| 责任 | 实际入口 |
| --- | --- |
| Core 数值能力 | `foc_impedance_tuning_design()` 输出 K/D 候选，`foc_impedance_feedforward_evaluate()` 按显式 J/B 和参考计算前馈，`foc_impedance_feasibility_evaluate()` 做静态诊断。只读遥测用 `foc_impedance_step()` 复算 H0 已接纳的同源请求。 |
| Foreground 生产者 | 初始化后由应用持有模型、参考、命令/生命周期序号。通过 `foc_runtime_publish_lifecycle_request()` 提交模式和状态操作，通过 `foc_runtime_publish_impedance_command()` 写入带实际源时间、序号、坐标和观察到的 Session 的合法命令。 |
| Encoder 与 H1 | `foc_virtual_motor_make_encoder_code()`、`foc_encoder_update()` 与 `foc_rotor_phase_from_counts()` 产生同源位置、速度、电角。 `foc_runtime_h1_step()` 生成该帧的外环请求。初始位置帧可用来供电角对齐，速度成立后才声明 IMPEDANCE 机械坐标。 |
| ADC 与 H0 | `foc_virtual_motor_make_adc()` 捕获 ADC 源时刻。 `foc_runtime_h0_step()` 独占模式、生命周期、Current/Pipeline/Safety 及输出事务。 |
| 监督、观察与 STOP | `foc_runtime_foreground_poll()` 周期监督，`foc_runtime_read_snapshot()` 读取接纳身份和输出，`foc_runtime_revoke_command()` 废止命令并请求 STOP。 |
| Host 输出 | `foc_device_sim_submit()` 验证模拟寄存器事务。调用方只把已接纳的 UPDATE 保存到下一时间段，并由 Virtual Motor 回放理想平均电压。 |

虚拟单调时钟有 100 µs 步长。H0、H1 及 Foreground 监督按各自 200、500、200 µs 到期执行，重合时时间次序为命令发布、H1、监督、H0。例行检查对齐周期、命令、Sensor 序号、时间戳、机械坐标 和 Session。实际遥测在 `1,100,200 µs` 用到来自 `1,100,000 µs` 的 Sensor，源码保留其捕获时刻，ADC 使用 `1,100,200 µs`。输出始终为 `physical_applied=false`。

| 时间（µs） | 操作 | 结果 |
| ---: | --- | --- |
| 200 | SET_MODE | APPLIED，IMPEDANCE、DISABLED、Session 1 |
| 500 | Foreground 发布首个合法目标，H1 接入 | 当前坐标及 Session 的同源位置和有效速度 |
| 600 | ARM | APPLIED，READY、Session 1 |
| 800 | START | APPLIED，RUNNING、Session 1 |
| 1,000 | 首个控制周期 | Adapter 确认第一个 UPDATE |
| 2,400,200 | STOP 服务 | INHIBIT，DISABLED、Session 2 |

## Host 参数与实测数据

4 极对，磁链 0.025 Wb，Kt 0.15 N·m/A，J 0.002 kg·m²，B 0.006 N·m·s/rad，编码器正向、65,536 CPR，Iq 上限 2.2 A，独立力矩上限 0.315 N·m。参数来自调用方显式已知的受控 Host 模型。Calibration 的 `usable` 候选可以作为经过身份与质量核对的另一种输入。Tuning 此次输出 K 0.648 N·m/rad、D 0.048 N·m·s/rad（18 rad/s，阻尼比 0.75）。两组均以应用命令在 1.45 s 调至 0.5508 与 0.0432。

两组各运行 2.4 s，位置保持后前进到 +0.22 rad，随后反向到 −0.10 rad。应用在同一时刻求取五次轨迹的位置、速度与加速度；唯一实验差异为 B 组为 IMPEDANCE 显式传入模型前馈，A 组填零。1.55–1.90 s 两组均施加 0.039 N·m 负载。反向统计以 0.90–1.30 s 的 2,001 个已接纳 H0 周期计算。位置与速度误差以已接纳参考和 Plant 状态计算。

### 错误路径

| 注入 | 观测 |
| --- | --- |
| Kt=0、K 超上界、D 为负 | ERR_CONFIG、ERR_INPUT、ERR_INPUT |
| CURRENT 下发布 IMPEDANCE、重复命令 | ERR_CONTROL、ERR_ORDER |
| 无条件 START、RUNNING 时尝试切 CURRENT | H0 拒绝两项生命周期请求。后者仍执行普通 H0 周期，沿用合法 IMPEDANCE。 |
| Sensor 重放原捕获时间 | 1,000 µs 源年龄，H1 ERR_ORDER，H0 ERR_ALIGNMENT，INHIBIT，3 → 3 |
| Encoder 帧错误 | H1 ERR_INPUT，H0 ERR_ALIGNMENT，先 INHIBIT，重复错误锁存 SAMPLE_INVALID（0x4），有效帧恢复后 UPDATE 仍为 3 |
| Adapter 拒绝 UPDATE | H0 ERR_CONTROL，Adapter 接纳次数 1 → 1，确认 INHIBIT，旧 Session 返回 ERR_ORDER |
| 合法运行后停止发布，但继续采样 | COMMAND_TIMEOUT（0x1），FAULT_LATCHED，13 → 13，旧引用被拒绝 |

[正式 Simulation 回归](../../simulation/tests/test_foc_runtime_impedance_virtual.c#L327) 单独断言适配器拒绝前后两个 PI 积分量完全相同。示例使用公开观察面核对提交计数、适配器 INHIBIT 和 Session。可恢复的软件 STOP 仍要求在新 Session 重新走合法的 ARM、START；锁存 Fault 还要求按原契约处理清除条件。
